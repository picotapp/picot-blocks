# 共通仕様 v0.1：HMI につなぐために先に決めること（0 章の 6 点は決定 2026-11-23「全部それで」）

根拠の表記：[一次] は各社の公開マニュアルで確かめたこと（文書番号・章）。「独自」はこのライブラリの設計判断で、理由を書く。

## 1. タンクのデモで使うブロック（基本版）

| HMI のテンプレート | ブロック | 基本版に入れるもの | 入れないもの（拡張版・後で） |
|---|---|---|---|
| `AnalogInput`（LT・TT・PT） | B-1 `PB_AnaMon` | スケーリング、NE43 判定、フィルタ、HH/H/L/LL＋共通ヒステリシス、警報ごとの有効・無効、停止・模擬、品質 | 遅延、変化率、代替値、NE107 入力、抑制 3 系統 |
| `DigitalInput`（LSHH） | **B-11 `PB_BinMon`（新規）** | 入力の反転、チャタリング防止の ON/OFF 遅延、警報（動作で警報）、停止・模擬、品質 | — |
| `PidController`（LIC） | B-6 `PB_Pid` | MAN/AUT/CAS、バンプレス切替、出力制限、PV 異常で MAN、出力トラッキング入力（J-7）、SP の範囲 | 偏差警報、PV トラッキング、ゲインスケジュール |
| `Pump`・`OnOffValve`（P・XV） | B-9 `PB_DevCore`（機器の核）＋ B-2・B-3 の薄い版 | 指令、アンサーバック（有無を設定）、監視時間（開・閉で別）、遷移超過の異常（DV-P2）、進み具合（DV-P1）、インターロック・パーミッシブ入力、運転時間・起動回数、現場/遠方 | 固着と未到達の区別（DV-2）、静止中の位置喪失（DV-3） |
| インターロック（IL-101） | **B-12 `PB_Intlk`（新規）** | 原因 8 点、動作中、原因ごとの状態、ファーストアウト、リセット可、手動・自動リセット、リセット要求の口 | バイパス、原因の AND・2oo3 |

- B-12 のロジック（どの原因でどの機器を止めるか）は C&E 表から作る（IL-P4）。FB は「原因をまとめてラッチし、状態を出す」だけで、機器への配線は C&E 表から生成する呼び出しコードで行う。
- ブロックの作る順番は、要件定義 3.3 の案（伝送器 → 機器の核 → PID）を変えない。タンクのデモに要る 5 種を基本版だけ先に揃える。

## 2. 1 ブロックのデータの並び（D-2・D-3）

全ブロック共通の型。Modbus の番地はブロックの先頭からの相対位置で決め、ブロックの先頭番地は対応表で決める（D-2）。

| 区画 | 書く人（D-3） | 中身 | 例（PB_AnaMon） |
|---|---|---|---|
| ① 状態ワード | block | 16 ビットの WORD を固定の数だけ。下の表 | STS・MODE・ALM・DIAG |
| ② 状態の値 | block | REAL | PV、PV（フィルタ前） |
| ③ 設定 | engineer | REAL・WORD。PLC の保持領域（リテイン）に置く（H-8） | レンジ、HH/H/L/LL、ヒステリシス、フィルタ時定数、警報の有効・無効（INH） |
| ④ 要求の口 | operator / engineer | 番号・項目・値・書いた人 → 処理済み番号・結果（3 章） | （AnaMon は停止・模擬の切替） |
| ⑤ プログラムの指令 | program | FB の入力として直接つなぐ（シーケンスから）。Modbus には出さない | — |

状態ワード（全ブロックで同じ位置・同じ意味のビットを使う）：

| ワード | 中身 |
|---|---|
| STS | bit0 運転中（On）／bit1 停止中（Out of service）／bit2 模擬中／bit3〜4 品質（0 Good・1 Uncertain・2 Bad）／bit5 品質の原因（0 プロセス・1 計器）／bit6 操作された値（模擬・代替）／bit7 設定異常（C-8）／bit8 dt 打ち切り（C-3） |
| MODE | 操作ブロックのモード（PID：0 MAN・1 AUT・2 CAS、機器：0 MAN・1 AUT ＋ bit8 現場）。監視ブロックは 0 |
| ALM | 発生中の警報のビット（ブロックの種類ごとに割り当てを決める。AnaMon：bit0 HH・bit1 H・bit2 L・bit3 LL・bit4 計器故障） |
| DIAG | ブロック固有の異常（機器：遷移超過、アンサーバック異常など） |

- 拡張版は、基本版の並びの**後ろに足す**（AI-10）。基本版から拡張版に差し替えても、先頭の位置は変わらない。
- 属性名（HMI）とレジスタの対応は、ブロックの種類ごとの対応表に 1 回だけ書く。HMI の画面定義・記録はタグ＋属性名で持つので（HMI の ST-3）、番地が変わっても画面と記録は変わらない。

## 3. 要求の口（H-4〜H-7）

画面からの書き込みを、ブロックが「採用するか、理由の番号付きで断るか」を決める仕組み。

| 入力 | 型 | 内容 |
|---|---|---|
| `ReqSeq` | INT | 要求の番号。変わったら 1 件処理する |
| `ReqItem` | INT | 項目の番号（ブロックの種類ごとの表。例：PID の 1 SP・2 MV・3 モード…） |
| `ReqValue` | REAL | 値。モードや指令も番号にして REAL で渡す |
| `ReqWriter` | INT | 1 運転員・2 エンジニア |

| 出力 | 型 | 内容 |
|---|---|---|
| `AckSeq` | INT | 処理した要求の番号（結果を書いてから進める） |
| `Result` | INT | 0 受け付け、1 以上は理由の番号（全ブロック共通の表。理由の文は HMI 側の対応表） |

- 書いた人の区分（運転員・エンジニア）と項目の組み合わせが許されるかは、ブロックが判断する（D-3、H-7）。ただし区分そのものは Node-RED の申告で、PLC は確かめられない。ログインと権限は HMI 側の課題として残す。
- 同じ値を書き続けても上書きしない（番号が変わったときだけ処理する。H-6）。
- **受付箱（`PB_ReqDispatch`）**：Modbus で全ブロックの口を出すと番地が増えるので、共通の受付箱を 1 つ置き、`ReqTag`（ブロックの番号）で各ブロックの口に振り分ける FB を用意する。OPC UA ではブロックごとの口を直接出せばよい。HMI のフェーズ3a設計（06）の受付箱は、この FB の使い方の 1 つになる。
- 理由の番号の表（案）：0 受け付け／1 項目が無い／2 この区分では書けない／3 レンジ外／4 このモードでは書けない／5 制限外（MV 上下限など）／6 カスケードの上位が無い／7 PV 異常のため AUT にできない／8 不正な値／9 インターロック中／10 インターロックは動作していない／11 原因が復帰していない／12 設定できる範囲外／13 大小の順番が合わない／14 起動条件（パーミッシブ）が揃っていない（2026-11-23 追加、PB_DevCore）／15 宛先のブロックが無い／16 ブロックが応答しない（15・16 は 2026-11-25 追加、PB_ReqDispatch）

## 4. 警報（A-4・A-5・A-6）

| ID | 案 | 理由 |
|---|---|---|
| A-4 | 基本版は**警報ごとの検出の有効・無効（INH、エンジニア）だけ**（三菱型 1 系統 [一次]）。運転員の棚上げ（Shelve）は HMI 側。プログラムの抑制（Suppress）は拡張版で足す | 棚上げは時間切れで戻すなど警報管理側の機能で、PLC の外に置く方が素直。HMI の属性 `enabled` と一致 |
| A-5 | **確認（ACK）とラッチはブロックで持たない。決定** | HMI で「警報の一覧（時刻・確認済み）は Node-RED」と決めた（2026-11-23）。ブロックは今出ているかだけを出す |
| A-6 | **優先度はブロックで持たない**。HMI の画面定義（警報の設定）で 1〜10 を持つ | 優先度は警報管理の設計（ISA-18.2 の警報データベース）で、PLC の動きに影響しない。レジスタも減る。HMI 基本設計 2.4 の「PLC と属性に持つ」を「HMI の設定に持つ」に直す |

## 5. ワード順・型（D-4、C-7）

- REAL は 32 ビット。ワード順は FB に関係ない（PLC のメモリーの並び）。**対応表に機種ごとに書く**（`wordOrder`）。
- 32 ビットの値のワード順は機種で違う（機種ごとのマニュアルで確かめて対応表に書く）。OpenPLC v4 は設定で選べる（既定は上位が先）。
- 整数は INT（16 ビット）。運転時間のように 32767 を超えうる値は DINT（2 ワード、ワード順は REAL と同じ）。

## 6. 時間・初回スキャン（C-2〜C-4）

HMI の接続には直接効かないが、ST を書く前に決める必要がある。要件定義の案（dt を入力、dt ≦ 0 は進めない、上限で打ち切って診断ビット、初期化入力で初期化）のまま決定にする案。
