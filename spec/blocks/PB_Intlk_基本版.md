# PB_Intlk（インターロック）基本版 仕様書 v0.3

根拠の表記：[一次] は各社の公開マニュアルで確かめたこと（文書番号・章）。「独自」はこのライブラリの設計判断で、理由を書く。

共通仕様：`../common/01_共通仕様_HMI接続まわり.md`（1 章の表：原因 8 点、動作中、原因ごとの状態、ファーストアウト、リセット可、手動・自動リセット、リセット要求の口）
兄弟ブロック：`PB_BinMon_基本版.md`（遅延の数え方）、`PB_DevCore_基本版.md`（Intlk 入力を受ける側）

この仕様が決まったら、ここから**手で**テストベクタを起こす（NF-4）。

## 1. 役割

最大 8 個の原因（BOOL）を OR でまとめ、どれか 1 つが動作したら **トリップ（`Trip` = TRUE）してラッチ**する。原因ごとの状態、最初に動いた原因（ファーストアウト）とその時刻、リセットできるか、を出す。リセットは要求の口で受ける（IL-P3）。

- **どの原因でどの機器を止めるかは、このブロックは持たない**。`Trip` を機器（PB_DevCore の `Intlk`）や調節計（PB_Pid の `TrkOn`）につなぐのは、C&E 表から作る呼び出しコード（IL-P4）。
- 機器の核（PB_DevCore）は「今インターロックが効いているか」を受けて安全側に倒すだけ。**ラッチ（リセットが要る）はこのブロックが持つ**（DevCore 13 章 論点 4）。Siemens の分類では Protect に当たる [一次]。
- 例：IL-101（TK-101 液面上上限 受入停止）。原因 1 = LSHH-101 の Active。Trip → XV-101 と P-101 の Intlk。

```
LSHH-101(PB_BinMon).Active ──► In1 ┐
                     （空き）  In2 ├─ PB_Intlk(IL-101) ── Trip ──┬─► XV-101(PB_DevCore).Intlk
                          …    In8 ┘                            └─► P-101(PB_DevCore).Intlk
```

基本版に入れないもの（拡張版）：バイパス（原因ごとの無効化）、AND・多数決（2oo3）、自己復帰型（Siemens の Intlock [一次]。原因が戻ったら即解除＝これは基本版の自動リセットで代わりになる）、プログラムからのリセット、9 個以上の原因（ファーストアウトを 2 つのブロックにまたがって判定できないため）。拡張版はこの仕様のデータの並びの**後ろに足す**。

## 2. 処理の順番

```
要求の口（リセット） → Init・設定異常 → 原因ごとの遅延 → トリップの判定・ファーストアウト → 自動リセット → 出力・状態ワード
```

| # | 処理 | 内容 |
|---|---|---|
| 1 | 要求の口 | リセット（項目 1）。受け付けたら同じスキャンでラッチを外す（5 章） |
| 2 | Init・設定異常 | 7 章 |
| 3 | 原因ごとの遅延 | 3 章。遅延の後の原因を `Cause`（bit0〜7）と呼ぶ |
| 4 | トリップの判定 | Trip = FALSE で Cause が 1 つでも TRUE → Trip = TRUE、ファーストアウトを記録（4 章） |
| 5 | 自動リセット | 設定が自動リセットなら、原因の入力がすべて FALSE になったスキャンで Trip = FALSE（5 章） |
| 6 | 出力 | 8 章 |

## 3. 原因ごとの遅延（13 章 論点 1）

- 原因ごとに ON 遅延 `Delay[i]`（0〜60 s、既定 0）を持つ。C&E 表の「遅延[s]」列をそのまま入れる。
- 数え方は BinMon の ON 遅延（BinMon 3 章・13-6）と同じ：入力 `In[i]` が TRUE のスキャンごとに経過時間に dt を足し、経過時間 ≧ Delay[i] で Cause[i] = TRUE。入力が FALSE になったら、**そのスキャンで** Cause[i] = FALSE、経過時間 0（OFF 遅延は持たない。戻りはリセットで扱うため）。
- 遅延 0 なら、入力が TRUE になったスキャンで Cause[i] = TRUE（dt ≦ 0 でも）。
- 遅延中（入力 TRUE、Cause FALSE）は DIAG bit2 を立てる。

## 4. トリップとファーストアウト（IL-P1）

| 出力 | 内容 |
|---|---|
| `Trip` | ラッチされたトリップ。機器の Intlk につなぐ |
| `Cause` | 原因の今の状態（遅延の後。bit0〜7 ＝ 原因 1〜8）。画面の「継続中／復帰」 |
| `Raw` | 原因の入力そのまま（遅延の前。保守用） |
| `Mem` | **このトリップのあいだに一度でも動作した原因**（bit）。トリップしたスキャンの Cause から始め、Trip 中に TRUE になった原因を足す。リセットで 0 |
| `First` | ファーストアウト（bit）。**トリップしたスキャンで TRUE だった原因すべて**（同じスキャンで 2 つ以上なら 2 つ以上立つ）。リセットまで変えない |
| `FirstNo` | First の中で一番小さい原因の番号（1〜8。トリップしていなければ 0）。画面に 1 つだけ出すとき用 |
| `FirstTime` | トリップしたスキャンの入力 `Now` の値（13 章 論点 3） |
| `ResetReady` | Trip = TRUE で、原因の入力（Raw）がすべて FALSE（IL-P2）。画面のリセットボタンの有効・無効 |

- トリップ中に別の原因が動作しても、First・FirstTime は変えない（それがファーストアウトの意味）。Mem にだけ足す。
- 同じスキャンで複数の原因が立ったときに順番を決めない理由（独自）：1 スキャンの中の順番は PLC には分からない。番号の小さい方を「最初」と表示すると、間違った原因を調べさせる。
- 設定 `FoEn`（ファーストアウトを記録する、既定 TRUE）が FALSE なら First・FirstNo・FirstTime は 0 のまま（C&E 表の「ファーストアウト なし」）。

## 5. リセット（IL-P2、IL-P3）

| 設定 `ResetMode` | 戻り方 |
|---|---|
| 0 手動（既定） | ResetReady のときに、要求の口でリセット（項目 1）を受け付けたら Trip = FALSE |
| 1 自動 | 原因の入力がすべて FALSE になったスキャンで Trip = FALSE（リセットの要求も受け付ける。結果は手動と同じ） |

- リセットで Trip・Mem・First・FirstNo・FirstTime を 0 にする。
- **原因の入力が 1 つでも TRUE なら、リセットは断る**（結果 11）。遅延中で Cause がまだ FALSE でも断る（ResetReady は Raw で見る）。理由（独自）：入っている原因を外して、遅延の後にすぐトリップし直すのは操作として意味がないため。
- トリップしていないときのリセットは断る（結果 10）。
- **リセットしても機器は動かない**。DevCore は Intlk が FALSE に戻っても安全側のまま（DevCore 4 章）。運転員が改めて起動・開を指令する。
- 書ける人は設定 `ResetBy` で決める（13 章 論点 7）：1 運転員（運転員とエンジニア）、2 エンジニアだけ。プログラム（3）は断る（結果 2）。C&E 表の「リセット権限」列をそのまま入れる。

## 6. 設定とその検査（C-8）

| 設定 | 型 | 既定値 | 内容 |
|---|---|---|---|
| `ResetMode` | INT | 0 | 0 手動・1 自動 |
| `ResetBy` | INT | 1 | 1 運転員・2 エンジニア |
| `FoEn` | BOOL | TRUE | ファーストアウトを記録する |
| `Delay[1..8]` | ARRAY OF REAL | 0 | 原因ごとの ON 遅延（s） |

- 設定は構造体 `PB_Intlk_Cfg` にまとめ、利用者のプログラムの保持領域に置いて `VAR_IN_OUT` で渡す（AnaMon 6.1 と同じ）。
- **設定は要求の口では変えない**（独自）：インターロックの中身は C&E 表が唯一の元データ（IL-P4）。画面から遅延やリセット方式を変えられると、C&E 表と食い違う。変えるときは C&E 表を直して、呼び出しコードを作り直す。
- 設定異常：Delay が NaN・無限大・負、ResetMode が 0/1 の外、ResetBy が 1/2 の外。60 s を超える遅延は設定異常にしない（BinMon 6 章と同じ）。設定異常のときの動きは 13 章 論点 5。

## 7. 時間・初期化（C-2〜C-4）

- `dt` の扱いは AnaMon と同じ（dt ≦ 0 は時間を進めない、1.0 s を超えたら 1.0 s で打ち切り DIAG bit0）。
- `Init` が TRUE のスキャン（13 章 論点 4）：ラッチを外し（Trip・Mem・First を 0）、経過時間を 0 にしてから、**今 TRUE の原因は遅延なしで Cause = TRUE** にして、同じスキャンでトリップを判定する。要求の口は AnaMon 13-10 と同じ（AckSeq を ReqSeq に合わせ、処理しない）。
  - 遅延なしにする理由：BinMon 7 章と同じ（電源を入れたとき、すでに入っている原因を遅延の間「正常」と見せない）。
- 設定異常から戻ったスキャンも Init と同じ扱い。

## 8. 入出力（FB のインターフェース）

| 区分 | 名前 | 型 | 内容 |
|---|---|---|---|
| 入力 | `In1`〜`In8` | BOOL | 原因（使わない原因は FALSE のまま） |
| 入力 | `Now` | UDINT | 今の時刻（13 章 論点 3。つながなければ 0） |
| 入力 | `dt` | REAL | 前回からの時間（s） |
| 入力 | `Init` | BOOL | 初期化 |
| 入力 | `ReqSeq` / `ReqItem` / `ReqValue` / `ReqWriter` | INT / INT / REAL / INT | 要求の口（D-7） |
| 入出力 | `Cfg` | PB_Intlk_Cfg | 設定（6 章） |
| 出力 | `Trip` | BOOL | トリップ（ラッチ） |
| 出力 | `ResetReady` | BOOL | リセットできる |
| 出力 | `Cause` / `Raw` / `Mem` / `First` | WORD | 4 章（bit0〜7） |
| 出力 | `FirstNo` | INT | 4 章 |
| 出力 | `FirstTime` | UDINT | 4 章 |
| 出力 | `STS` / `MODE` / `ALM` / `DIAG` | WORD | 状態ワード |
| 出力 | `AckSeq` / `Result` | INT | 要求の口の返事 |

- 原因を配列でなく `In1`〜`In8` にした理由（独自）：FBD・ラダーで 1 本ずつ線をつなげるように。

状態ワードのビット：

| ワード | ビット |
|---|---|
| STS | 共通（bit0 運転中・7 設定異常・8 dt 打ち切り）。品質は使わない（0） |
| MODE | 常に 0 |
| ALM | 常に 0（13 章 論点 6） |
| DIAG | bit0 dt 打ち切り・1 設定異常・2 遅延中の原因がある |

## 9. 要求の口の項目

| 項目番号 | 内容 | 書ける人 | 値 | 断る理由 |
|---|---|---|---|---|
| 1 | リセット | ResetBy で決める（5 章） | 1 | 10（トリップしていない）、11（原因が復帰していない） |

- 断る順番：項目が無い 1 → 書ける人でない 2 → 値が 1 でない（NaN・無限大も）8 → トリップしていない 10 → 原因の入力が TRUE 11。同じ番号の要求は何もしない（AnaMon 13-14）。
- 10・11 は共通仕様の番号の表にもうある（インターロック用に取ってあった番号）。

## 10. Modbus の並び（ブロックの先頭からの相対位置、16 ビットワード）

| 位置 | 中身 | 書く人 |
|---|---|---|
| 0〜3 | STS・MODE・ALM・DIAG | block |
| 4 | VAL：bit0 Trip・bit1 ResetReady・bit2 ResetMode（1 自動）・bit3 FoEn・bit4〜5 ResetBy（1・2） | block |
| 5 | Cause（bit0〜7） | block |
| 6 | Raw | block |
| 7 | Mem | block |
| 8 | First | block |
| 9 | FirstNo | block |
| 10〜11 | FirstTime | block |
| 12〜15 | 要求の口：ReqSeq・ReqItem・ReqWriter・予備 | operator / engineer |
| 16〜17 | 要求の口：ReqValue | operator / engineer |
| 18〜19 | AckSeq・Result | block |
| 20〜35 | Delay[1]〜Delay[8]（REAL × 8。読むだけ。C&E 表との突き合わせ C-11 用） | block |

- 計 36 ワード。REAL・UDINT は偶数の位置から始める。受付箱を使う構成では 12〜19 は出さない（AnaMon と同じ）。

## 11. PICOT HMI の属性との対応（Interlock）

今の HMI の `InterlockState`（`src/core/types.ts`）：

| HMI | ここ |
|---|---|
| `active` | Trip |
| `causes`（タグ → 継続中か） | Cause の bit。bit の番号 → タグは C&E 表の行の順（Node-RED が変換） |
| `firstOut`（タグ） | FirstNo → タグ。First に 2 つ以上立っているときの出し方は HMI の作業（今は 1 つだけ） |
| `firstOutTime` | FirstTime を時刻の文字列にする（Node-RED） |
| `resetReady` | ResetReady |
| リセットボタン | 要求の口 項目 1 |

- 今の HMI は「リセット可」を `active && 全原因が戻った` で作っている。ここでは Raw（遅延の前）で見るので、遅延中の原因があると押せない。デモの原因（LSHH-101）は遅延 0 なので違いは出ない。
- Mem（トリップ中に一度でも動作した原因）は今の HMI に無い。画面に出すなら HMI 側に属性を足す（HMI の作業）。

## 12. 呼び出しコードの例（C&E 表から作るもの）

```
(* IL-101：TK-101 液面上上限 受入停止 *)
IL101(In1 := LSHH101.Active, Now := ClockS, dt := Dt, Init := FirstScan,
      ReqSeq := ..., Cfg := IL101_Cfg);
XV101(Intlk := IL101.Trip, ...);
P101(Intlk := IL101.Trip, ...);
```

- **インターロックは機器より先に呼ぶ**。逆だと、トリップが機器に届くのが 1 スキャン遅れる。
- 同じ機器を 2 つ以上のインターロックが止めるときは `Intlk := IL101.Trip OR IL102.Trip`。
- C&E 表の原因条件と、つなぐ出力：`動作` → BinMon.Active、`HH`・`LL` → AnaMon の警報の出力、`故障` → BinMon.Bad・AnaMon の Bad（13 章 論点 2）。

## 13. 決めたこと（2026-11-24）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 原因ごとの遅延 | **このブロックに持つ**（ON 遅延だけ、0〜60 s） | C&E 表に「遅延[s]」の列があり、C&E 表を唯一の元データにするため（IL-P4）。BinMon の遅延はチャタリング防止（計器の都合）、ここの遅延はインターロックの決めごと、と役割を分ける |
| 2 | 計器の異常（Bad）をどう扱うか | **入力を増やさない**。異常でも止めたいときは、C&E 表に「故障」の行を別の原因として書き、Bad をつなぐ | 「異常なら止める／止めない」はインターロックごとに違う判断で、C&E 表に見える形で書くべき。ブロックに隠れた規則を持たせない（BinMon 12 章 論点 2 で「B-12 で決める」とした件） |
| 3 | ファーストアウトの時刻 | 入力 `Now`（UDINT、PLC の時計の秒。Unix 時刻を推奨）を**トリップしたスキャンで写すだけ**。1 秒より細かい時刻は持たない | 時計の読み方は PLC メーカーごとに違うので、ブロックの外で読む。原因の順番はファーストアウトのビットで分かるので、時刻は記録用。ミリ秒が要るなら拡張版で足す |
| 4 | 電源投入（Init） | **ラッチを保持しない**。Init で外して、今入っている原因で遅延なしにトリップし直す | 電源が切れていた間に原因が戻っていても、機器は DevCore の Init で安全側にいるので危なくない。ラッチを保持すると、保持領域が壊れたときの動きを決める必要が出る |
| 5 | 設定異常のとき | **トリップ側にする**（Trip = TRUE、First は 0。リセットは受け付けず結果 11）。戻ったら Init と同じ | 安全のためのブロックで、何をすべきか分からないときは止める側に倒す（DevCore 14-16 で設定異常は安全側にしたのと同じ）。設定は画面から変えないので、起きるのは試運転のときだけ |
| 6 | 警報 | **出さない**（ALM は常に 0） | 原因のブロック（LSHH-101 など）が警報を出している。トリップでもう 1 つ出すと、同じことで 2 つ鳴る（ISA-18.2 の重複警報）。トリップは IL の札とファーストアウトで見せる |
| 7 | リセットできる人 | **設定 `ResetBy` で運転員／エンジニア**を選ぶ。プログラムからのリセットは基本版では持たない | C&E 表の「リセット権限」列。プログラムが勝手にラッチを外すと、ラッチの意味が無くなる。シーケンスで外したい場面は拡張版で考える |

## 14. テストベクタを起こして決めた細部（2026-11-24、案）

| # | 場面 | 決めたこと | 理由 |
|---|---|---|---|
| 14-1 | 1 スキャンの順番 | ①Raw を作る → ②要求の口 → ③設定異常・Init → ④原因ごとの遅延（Cause）→ ⑤トリップの判定・ファーストアウト・Mem → ⑥自動リセット → ⑦出力・状態ワード | ②のリセットの判定（原因の入力がすべて FALSE か）に、今のスキャンの入力を使うため Raw を先に作る |
| 14-2 | リセットを受け付けたスキャン | ②で Trip・Mem・First・FirstNo・FirstTime を 0 にする。Raw がすべて FALSE なので⑤でトリップし直すことはない | |
| 14-3 | 遅延の数え方 | 入力が TRUE で Cause が FALSE のスキャンごとに経過時間に dt を足し、経過時間 ≧ Delay で Cause = TRUE。入力が FALSE になったら Cause = FALSE・経過時間 0。Delay 0 なら dt に関係なくそのスキャンで TRUE | BinMon 13-6 と同じ |
| 14-4 | Mem・First に入るもの | 遅延の後の Cause だけ（遅延中の原因は入れない）。トリップしたスキャンで Mem = First = Cause（FoEn が FALSE でも Mem は記録する） | 「動作した原因」はインターロックが効く条件になったもの |
| 14-5 | 自動リセット | ⑥で Trip かつ Raw がすべて FALSE なら Trip を外す（14-2 と同じものを 0 にする）。遅延中の原因があれば外さない | 手動リセットの ResetReady と同じ条件 |
| 14-6 | ResetReady | ⑦の時点で Trip かつ Raw がすべて FALSE。自動リセットでは⑥で外れるので、出力は常に FALSE になる | |
| 14-7 | 設定異常 | Trip = TRUE。Mem・First・FirstNo・FirstTime は 0、経過時間は 0、Cause = Raw（表示用、遅延なし）、ResetReady = FALSE。リセットの要求は、項目・書ける人・値を確かめたあと結果 11（書ける人は ResetBy が 1 なら運転員・エンジニア、それ以外はエンジニアだけ）。戻ったスキャンは Init と同じ | 13 章 論点 5 |
| 14-8 | Init | 要求の口は処理しない（AckSeq = ReqSeq、Result はそのまま）。ラッチと経過時間を 0 にし、Cause = Raw（遅延なし）にして⑤で判定する | 7 章 |
| 14-9 | Now | そのまま写す（範囲は確かめない）。JS では 0〜2^32−1 の整数として扱う | |

テストベクタの時間は 0.25 s の倍数で組む（AnaMon 13.1 と同じ理由）。
