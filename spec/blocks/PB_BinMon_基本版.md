## 1. 役割

レベルスイッチ・圧力スイッチ・リミットスイッチなどの接点入力（DI）を、**プロセスの意味の状態「動作（Active）」**にする。反転、チャタリング防止の ON/OFF 遅延、動作で警報、入力異常、停止・模擬、品質を持つ。運転員の手動・自動は持たない（M-1）。

- **接点の NO／NC は設定 `Invert` で切り替える**：NO（常時開、閉じたら動作）は `Invert = FALSE`、NC（常時閉、開いたら動作）は `Invert = TRUE`。
- 例：LSHH-101（液面上上限スイッチ）。フェイルセーフの配線（正常で接点が閉、液面が上がると開＝NC）なので `Invert = TRUE`。液面が上がったとき Active = TRUE になり、断線しても Active = TRUE（安全側）に倒れる。
- 機器のアンサーバック（運転中・開・閉）はこのブロックを通さず、機器の核（B-9）に直接つなぐ。このブロックは「単独で監視する接点」用。

基本版に入れないもの（拡張版）：ばたつきの検出（決めた時間内の変化回数で警報）、「動作していないこと」で警報（12 章 論点 1）、プログラムによる抑制。拡張版はこの仕様のデータの並びの**後ろに足す**。

## 2. 処理の順番

```
入力の選択 → 反転 → 入力異常の判定 → ON/OFF 遅延 → 異常時の値 → 警報 → 品質 → 状態ワード
（模擬なら模擬値）
```

| # | 処理 | 内容 | 根拠 |
|---|---|---|---|
| 1 | 入力の選択 | 模擬中は `SimValue`（**反転後の意味の値**。TRUE＝動作）を使い、2・3 を飛ばす（遅延・警報は通す）。それ以外は入力 `In` | AnaMon と同じ（模擬値でフィルタ・警報を試せる）。模擬値を意味の値にする理由（独自）：運転員・エンジニアは配線の向きを気にせず「動作させる」と考えるため |
| 2 | 反転 | `InAct` = In XOR `Invert` | フェイルセーフの配線（常時閉）を扱うため |
| 3 | 入力異常の判定 | 入力 `ChFault`（DI ユニットの断線・短絡の検出ビット）が TRUE なら入力異常。遅延なしで判定し、FALSE になったスキャンで戻る | 断線検出つきのユニット（NAMUR 近接スイッチ用など）を使うとき。検出の無いユニットでは FALSE のまま |
| 4 | ON/OFF 遅延 | 3 章 | チャタリング防止（B-11） |
| 5 | 異常時の値 | 入力異常のあいだの Active は `FailMode` で決める：0 保持（既定）・1 動作にする・2 非動作にする | 12 章 論点 2 |
| 6 | 警報 | 4 章 | A-4〜A-6 |
| 7 | 品質 | 5 章 | Q-1、M-4 |

## 3. ON/OFF 遅延

| 変わる向き | 条件 |
|---|---|
| 非動作 → 動作 | InAct が TRUE のまま `OnDelay` 秒続いたら Active = TRUE |
| 動作 → 非動作 | InAct が FALSE のまま `OffDelay` 秒続いたら Active = FALSE |

- 数え方は AnaMon の故障の ON 遅延（13-6）と同じ：InAct ≠ Active のスキャンごとに経過時間に dt を足し、経過時間 ≧ その向きの遅延時間で Active を切り替えて経過時間を 0 に戻す。InAct = Active に戻ったら経過時間を 0 に戻す。遅延 0 なら、そのスキャンで切り替える（dt ≦ 0 でも切り替える）。
- 遅延中（InAct ≠ Active で経過時間を数えている間）は DIAG bit3 を立てる（保守で「入力は変わったが、まだ待っている」を見られるように）。品質は Good のまま。
- 遅延中に遅延時間を変えたら、経過時間はそのまま、新しい遅延時間と比べる（要求の口はスキャンの最初に処理するので、変えたスキャンから効く。13-1）。
- ON 遅延と OFF 遅延を別々に持つ理由：チャタリングの出方は向きで違う（例：液面スイッチは波立ちで「動作 → 戻り」が短く繰り返す）。
- 入力異常のあいだは経過時間を 0 にして数えない（壊れた入力で切り替えない）。
- 範囲：0〜60 s。それより長い待ちはプロセスのロジック（シーケンス側）で作るもの、とする（独自）。

## 4. 警報

| ALM のビット | 名前 | 発生 | 戻り |
|---|---|---|---|
| bit0 | 動作 | Active = TRUE、かつ有効（Inh bit0 = 0） | Active = FALSE |
| bit1 | 入力異常 | 入力異常（ChFault） | ChFault が戻る |

- 「動作」の判定に遅延後の Active を使う（警報もチャタリングしない）。
- 入力異常・停止中は「動作」を出さない（AnaMon と同じ）。FailMode = 1 で Active を TRUE にしていても「動作」は出さず、「入力異常」だけを出す（理由（独自）：原因は計器の異常で、プロセスが動作したわけではないため）。
- 停止中は「入力異常」も出さない（AnaMon 13-16 と同じ）。
- 模擬中は模擬値で「動作」を判定する（AnaMon と同じ）。
- 「入力異常」の有効・無効は持たない（AnaMon の計器故障と同じく常に出す）。
- 確認（ACK）・ラッチ・優先度は持たない（A-5・A-6）。PICOT HMI の LSHH-101 の優先度 9 は画面定義の値。

## 5. 品質とモード

| 状態 | STS の品質（bit3〜4） | 原因（bit5） | 操作された値（bit6） |
|---|---|---|---|
| 正常（遅延中も含む） | 0 Good | — | 0 |
| 入力異常、設定異常 | 2 Bad | 1 計器 | 0 |
| 停止中 | 3 停止中 | — | 0 |
| 模擬中 | 0 Good | — | 1 |

- Uncertain は使わない（ディジタルにはレンジ外が無いため）。
- モードは「運転中／停止中」の 2 つ。停止中は Active を保持し、警報を出さない（M-4）。停止の操作は**エンジニアだけ**（AnaMon と同じ）。
- 模擬と停止の関係、停止中の STS bit2・bit6 の扱いは AnaMon（5 章、13-16）と同じ。
- 設定異常（6 章）のときは Active を保持し、Bad（計器）。警報は出さない。
- 出力 `Bad`：品質が Bad または停止中のとき TRUE（インターロックなど次のブロックに渡す用）。

## 6. 設定とその検査（C-8）

| 設定 | 型 | 既定値 | 書ける範囲（要求の口で検査） |
|---|---|---|---|
| `Invert` | BOOL | FALSE | FALSE = NO（常時開）・TRUE = NC（常時閉）。要求の口では変えない |
| `OnDelay` / `OffDelay` | REAL | 0 / 0 | 0〜60 s |
| `Inh` | WORD | 16#0001（動作の警報は無効） | bit0 動作 |
| `FailMode` | INT | 0 | 0 保持・1 動作・2 非動作（要求の口では変えない） |
| `SimValue` | BOOL | FALSE | 0・1 |

- 設定は構造体 `PB_BinMon_Cfg` にまとめ、利用者のプログラムの保持領域に置いて `VAR_IN_OUT` で渡す（AnaMon 6.1 と同じ）。
- 設定異常にするのは計算できない設定だけ：OnDelay・OffDelay が NaN・無限大・負、FailMode が 0〜2 の外（AnaMon 13-17 と同じ考え方）。60 s を超える遅延は要求の口では断るが、プログラムで入れられたら設定異常にせずそのまま使う。
- 既定で警報を無効にする理由は AnaMon と同じ（設定前に鳴り続けないように）。
- `Invert`・`FailMode` は配線と安全側の決めごとなので、試運転のときにプログラムで決める（独自）。

## 7. 時間・初期化（C-2〜C-4）

- `dt` の扱いは AnaMon と同じ（dt ≦ 0 は時間を進めない、1.0 s を超えたら 1.0 s で打ち切り DIAG bit0）。
- `Init` が TRUE のスキャン：**Active を今の InAct に遅延なしで合わせる**、経過時間を 0、警報を消してから同じスキャンで判定し直す。要求の口は AnaMon 13-10 と同じ（AckSeq を ReqSeq に合わせ、処理しない）。
  - 遅延なしで合わせる理由（独自）：電源を入れたとき、すでに動作しているスイッチを遅延の間「非動作」と見せないため（インターロックが遅れて動くのを防ぐ）。
- 停止 → 運転、模擬 入 → 切、設定異常から戻ったスキャンも Init と同じ扱い（AnaMon 13-9・13-19 と同じ）。

## 8. 入出力（FB のインターフェース）

| 区分 | 名前 | 型 | 内容 |
|---|---|---|---|
| 入力 | `In` | BOOL | DI の接点（配線のままの値） |
| 入力 | `ChFault` | BOOL | DI ユニットの断線・短絡の検出ビット（無ければ FALSE） |
| 入力 | `dt` | REAL | 前回からの時間（s） |
| 入力 | `Init` | BOOL | 初期化 |
| 入力 | `ReqSeq` / `ReqItem` / `ReqValue` / `ReqWriter` | INT / INT / REAL / INT | 要求の口（D-7） |
| 入出力 | `Cfg` | PB_BinMon_Cfg | 設定（6 章） |
| 出力 | `Active` | BOOL | 動作（反転・遅延の後。インターロックの原因などに使う） |
| 出力 | `InAct` | BOOL | 反転の後・遅延の前の値（保守用。模擬中は模擬値） |
| 出力 | `ActAlm` / `Fail` | BOOL | 動作の警報・入力異常（ALM と同じ内容）。`ActAlm` は `ALM` と同じ名前にならないようにした（ST は大文字・小文字を区別しない） |
| 出力 | `Bad` | BOOL | 品質が Bad または停止中 |
| 出力 | `STS` / `MODE` / `ALM` / `DIAG` | WORD | 状態ワード |
| 出力 | `AckSeq` / `Result` | INT | 要求の口の返事 |

状態ワードのビット：

| ワード | ビット |
|---|---|
| STS | 共通（bit0 運転中・1 停止中・2 模擬中・3〜4 品質・5 原因・6 操作された値・7 設定異常・8 dt 打ち切り） |
| MODE | 常に 0（監視ブロック） |
| ALM | bit0 動作・1 入力異常 |
| DIAG | bit0 dt 打ち切り・1 設定異常・2 ChFault・3 遅延中 |

## 9. 要求の口の項目

| 項目番号 | 内容 | 書ける人 | 値 |
|---|---|---|---|
| 1 | モード | エンジニアだけ | 0 運転中・1 停止中 |
| 2 | 模擬 | エンジニア | 0 切・1 入 |
| 3 | 模擬値 | エンジニア | 0 非動作・1 動作 |
| 10 | ON 遅延 | エンジニア | s |
| 11 | OFF 遅延 | エンジニア | s |
| 16 | 動作の警報の有効・無効 | エンジニア | 0 無効・1 有効 |

- 番号は AnaMon と揃えた（1〜3 は同じ意味、16 は「1 つ目の警報の有効・無効」）。
- 結果の番号：項目が無い → 1、書ける人でない（運転員・プログラム）→ 2、NaN・無限大・0/1 以外 → 8、遅延が 0〜60 s の外 → 12。複数に当たるときはこの順で先に当たったもの（AnaMon の実装と同じ順）。同じ番号の要求は何もしない（AnaMon 13-14）。

## 10. Modbus の並び（ブロックの先頭からの相対位置、16 ビットワード）

| 位置 | 中身 | 書く人 |
|---|---|---|
| 0〜3 | STS・MODE・ALM・DIAG | block |
| 4 | VAL：bit0 Active・bit1 InAct・bit2 In（配線のままの値） | block |
| 5 | 予備 | — |
| 6〜7 | OnDelay | engineer（要求の口経由） |
| 8〜9 | OffDelay | engineer（要求の口経由） |
| 10 | Inh | engineer（要求の口経由） |
| 11 | bit0 SimValue | engineer（要求の口経由） |
| 12〜15 | 要求の口：ReqSeq・ReqItem・ReqWriter・予備 | operator / engineer |
| 16〜17 | 要求の口：ReqValue | operator / engineer |
| 18〜19 | AckSeq・Result | block |

- 計 20 ワード。REAL は偶数の位置から始める。受付箱を使う構成では 12〜19 は出さない（AnaMon と同じ）。
- 状態の値（AnaMon の PV に当たるもの）が BOOL なので、REAL ではなくビットのワード VAL にした（D-1）。

## 11. PICOT HMI の属性との対応（DigitalInput）

| HMI の属性 | ここ |
|---|---|
| `active` | Active（VAL bit0） |
| `alarms`（一覧） | ALM のビットから Node-RED が作る |

- 今の HMI の `DigitalInput` には `active` と警報しかない。品質・停止・模擬を画面に出すなら、HMI 側に `quality`・`qualityCause`・`mode`・`simulate` を足す（AnalogInput と同じ名前・同じ書く人）。HMI の作業で、この仕様の決定には影響しない。

## 12. 決めたこと（2026-11-23）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 警報の出し方 | **「動作で警報」だけ**。「動作でないことで警報」が要るときは Invert で意味を逆にする | LSHH・PSL など監視用の接点はほとんど「動作＝異常」。両方を持つと設定が 1 つ増え、Invert と組み合わせて分かりにくくなる |
| 2 | 入力異常（ChFault）のときの Active | **設定 FailMode で選ぶ。既定は 0 保持**（1 動作・2 非動作も選べる） | AnaMon（保持）と揃える。インターロックに使う接点を「異常なら止める」にしたいときは、FailMode = 1 にするか、インターロック側で Bad を原因に入れる（B-12 の仕様で決める）。フェイルセーフの配線なら断線は ChFault が無くても「動作」に倒れる |
| 3 | 遅延の範囲と Init | ON・OFF を別々に 0〜60 s。Init では遅延なしで今の入力に合わせる | 3 章・7 章 |
| 4 | 模擬値に遅延をかけるか | **かける**（模擬値も遅延・警報を通す） | AnaMon で模擬値にフィルタをかけるのと揃える。遅延の設定の確認にも使える |

## 13. テストベクタを起こして決めた細部（2026-11-23、案）

| # | 場面 | 決めたこと | 理由 |
|---|---|---|---|
| 13-1 | 1 スキャンの順番 | ①要求の口 → ②モード・Init → ③入力の選択・反転 → ④入力異常 → ⑤遅延 → ⑥異常時の値 → ⑦警報 → ⑧品質・状態ワード | AnaMon 13-1 と同じ |
| 13-2 | 入力異常から戻ったスキャン | Init と同じ扱い（Active を今の InAct に遅延なしで合わせる） | FailMode 1・2 で無理に倒した値や、保持した古い値から遅延を数え直さないため。AnaMon 13-7 の「戻ったら判定し直す」と同じ考え方 |
| 13-3 | 模擬 切 → 入 | Init 扱いにしない（模擬値も遅延を通る。12 章 4） | 模擬 入 → 切 は Init 扱い（AnaMon 13-9） |
| 13-4 | 模擬中の ChFault | 見ない（Fail・DIAG bit2 は 0）。AnaMon 13-8 と同じ | |
| 13-5 | 停止中・設定異常の InAct | 入力 In から計算し続ける（保守用。AnaMon の mA と同じ）。Active は保持 | |
| 13-6 | 遅延の比べ方 | 経過時間 ≧ 遅延時間で切り替え（REAL で比べる）。遅延時間が 0 なら dt に関係なくそのスキャンで切り替え | AnaMon 13-6 と同じ |

テストベクタの時間は 0.25 s の倍数で組む（AnaMon 13.1 と同じ理由）。
