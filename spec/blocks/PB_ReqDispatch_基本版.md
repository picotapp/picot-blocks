# PB_ReqDispatch（要求の受付箱）基本版 仕様書 v0.2

根拠の表記：[一次] は各社の公開マニュアルで確かめたこと（文書番号・章）。「独自」はこのライブラリの設計判断で、理由を書く。

共通仕様：`../common/01_共通仕様_HMI接続まわり.md` 3 章（要求の口と受付箱）

この仕様が決まったら、ここから**手で**テストベクタを起こす（NF-4）。

## 1. 役割

Modbus で、全ブロックの要求の口（ReqSeq・ReqItem・ReqValue・ReqWriter → AckSeq・Result。D-7）を 1 つずつ外に出すと、ブロックごとに 8 ワード要る。このブロックは **PLC に受付箱を 1 つだけ置き、宛先の番号で各ブロックの要求の口に振り分ける**。

```
Node-RED ──(Modbus)──► 受付箱：Seq・Tag・Item・Value・Writer
                              │
                       PB_ReqDispatch
                              │ Tag の番号の口だけ Seq を進める
          ┌───────────────────┼───────────────────┐
     Ports[1]            Ports[2]  …          Ports[n]
    LT-101(AnaMon)      LIC-101(Pid)        IL-101(Intlk)
          └──── AckSeq・Result が返ったら、受付箱の Ack・Result に写す ──┘
```

- **書けるかどうかの判断はしない**。項目・書いた人・値の検査は、宛先のブロックの要求の口が行う（D-3）。このブロックは運ぶだけ。
- OPC UA のように口を直接出せるときは、このブロックは要らない（共通仕様 3 章）。
- 1 件ずつ順に処理する（Node-RED が並べて送る。HMI 06 の 2 章 4）。

基本版に入れないもの（拡張版）：受付箱を 2 つ以上（運転員用・エンジニア用など）、記録（誰がいつ何を書いたか。記録は Node-RED 側：HMI ST-3）。

## 2. 振り分けの仕組み（11 章 論点 1）

宛先ごとの口は、構造体の配列 `Ports`（`ARRAY[1..64] OF PB_ReqPort`、VAR_IN_OUT）で受け渡す。

| `PB_ReqPort` の要素 | 型 | 書く人 | 内容 |
|---|---|---|---|
| `Seq` | INT | このブロック | 宛先の ReqSeq につなぐ |
| `Item` / `Value` / `Writer` | INT / REAL / INT | このブロック | 宛先の ReqItem・ReqValue・ReqWriter につなぐ |
| `AckSeq` / `Result` | INT | 呼び出しコード | 宛先の AckSeq・Result を写す |

呼び出しコード（対応表から作る。12 章）：

```
DISP(BoxSeq := MB_Seq, BoxTag := MB_Tag, ..., dt := Dt, Init := FirstScan, Cfg := DispCfg, Ports := Ports);
LIC101(ReqSeq := Ports[2].Seq, ReqItem := Ports[2].Item, ReqValue := Ports[2].Value, ReqWriter := Ports[2].Writer, ...);
Ports[2].AckSeq := LIC101.AckSeq;  Ports[2].Result := LIC101.Result;
```

- 宛先の口の Seq は、**その宛先に要求を渡すときだけ** 1 進める（1〜32767 を回る。0 には戻さない）。Item・Value・Writer は全部の口に書いてもよいが、Seq が変わらない口は何もしない（D-7「番号が変わったときだけ処理」）。
- 理由（独自）：FB の入力に別の FB のインスタンスを渡す書き方は、対応していない機種がある（C-1：多くの機種で通る書き方に限る）。構造体の配列なら、多くの機種で書ける。

## 3. 1 件の流れ

| # | スキャン | このブロックがすること |
|---|---|---|
| 1 | 受付箱の `BoxSeq` が `BoxAck` と違い、処理中でない | 宛先 `BoxTag` を確かめる（範囲外・使っていない番号なら結果 15 で返事して終わり）。宛先の口に Item・Value・Writer を書き、Seq を 1 進める。**処理中**にして、待ち時間を 0 にする |
| 2 | 処理中で、宛先の口の AckSeq = Seq | `BoxResult` = 口の Result、`BoxAck` = 受け付けた BoxSeq。処理中を外す |
| 3 | 処理中で、待ち時間 ≧ `TimeOut` | `BoxResult` = 16（ブロックが応答しない）、`BoxAck` = 受け付けた BoxSeq。処理中を外す |

- 宛先のブロックをこのブロックの**後に**呼ぶと、宛先は同じスキャンで処理し、返事は次のスキャンで受付箱に出る（1 件 2 スキャン）。前に呼ぶと 3 スキャン。どちらでも動く。
- 処理中に `BoxSeq` が変わったら、今の 1 件を終えてから新しい方を処理する（受付箱の中身はそのとき読み直す）。途中の要求は捨てない・上書きしない。
- 返事が 2 のスキャンで来て、同じスキャンで新しい要求があれば、次のスキャンで処理する（1 スキャンに 1 件だけ動かす。テストを単純にするため、独自）。
- 時間切れの後に宛先が遅れて処理しても、このブロックは無視する（処理中でないため）。HMI には「応答しない」と出ているのに値が変わることがある。宛先を呼び忘れた配線の誤り以外では起きないので、試運転で直す（利用者向けの注意に書く）。

## 4. 結果の番号（新しく足すもの）

| 番号 | 意味 | 出すところ |
|---|---|---|
| 15 | 宛先のブロックが無い（Tag が 1〜NumPorts の外） | このブロック |
| 16 | ブロックが応答しない（TimeOut を過ぎた） | このブロック |

- 0〜14 は宛先のブロックの結果をそのまま写す。共通仕様の番号の表に 15・16 を足す（決まったら）。

## 5. 生存カウンター（11 章 論点 4）

- 出力 `Alive`（INT）を毎スキャン 1 進める（0〜32767 を回る）。Node-RED は、決めた時間これが変わらなければ通信断・PLC 停止として画面をグレーにする（HMI 06 の番地 1024、H-3）。
- dt ≦ 0 のスキャンでも進める（スキャンしていることを示すため）。

## 6. 設定とその検査（C-8）

| 設定 | 型 | 既定値 | 内容 |
|---|---|---|---|
| `NumPorts` | INT | 64 | 使う口の数（1〜64）。Tag がこれを超えたら結果 15 |
| `TimeOut` | REAL | 1.0 | 返事を待つ時間（s）。0.1〜10 |

- 要求の口では変えない（このブロック自身は要求の口を持たない）。
- 設定異常：NumPorts が 1〜64 の外、TimeOut が NaN・無限大・0 以下。設定異常のあいだは受付箱を処理しない（BoxAck を進めない。Node-RED は 2 秒で「PLC が応答しません」になる）。処理中の 1 件は捨てる。戻ったら Init と同じ。
- 10 s を超える TimeOut は設定異常にしない（他のブロックの「範囲外は要求の口では断るが、プログラムで入れられたら使う」と同じ）。

## 7. 時間・初期化（C-2〜C-4）

- dt は AnaMon と同じ（dt ≦ 0 は待ち時間を進めない、1.0 s を超えたら 1.0 s で打ち切り DIAG bit0）。
- `Init` が TRUE のスキャン：処理中を外し、`BoxAck` = `BoxSeq`（入っていた要求は処理しない。各ブロックの Init と同じ考え方、AnaMon 13-10）。BoxResult はそのまま。Ports には触らない。
- **電源投入では、このブロックと全部の宛先を同じスキャンで Init する**。宛先の Init は口の Seq に AckSeq を合わせるだけで Result を変えないので、宛先だけ後で Init すると、古い Result を返事として写すことがある（独自。呼び出しコードの決まりにする）。

## 8. 入出力

| 区分 | 名前 | 型 | 内容 |
|---|---|---|---|
| 入力 | `BoxSeq` / `BoxTag` / `BoxItem` / `BoxValue` / `BoxWriter` | INT / INT / INT / REAL / INT | 受付箱（Node-RED が書く） |
| 入力 | `dt` / `Init` | REAL / BOOL | |
| 入出力 | `Cfg` | PB_ReqDispatch_Cfg | 6 章 |
| 入出力 | `Ports` | ARRAY[1..64] OF PB_ReqPort | 2 章 |
| 出力 | `BoxAck` / `BoxResult` | INT | 受付箱の返事 |
| 出力 | `Busy` | BOOL | 処理中 |
| 出力 | `Alive` | INT | 生存カウンター |
| 出力 | `STS` / `MODE` / `ALM` / `DIAG` | WORD | 状態ワード |

| ワード | ビット |
|---|---|
| STS | bit0 運転中・7 設定異常・8 dt 打ち切り |
| MODE・ALM | 常に 0 |
| DIAG | bit0 dt 打ち切り・1 設定異常・2 処理中・3 最後の 1 件が時間切れ（次の要求を受けるまで） |

## 9. Modbus の並び（受付箱、16 ビットワード）

| 位置 | 中身 | 書く人 |
|---|---|---|
| 0 | Alive | block |
| 1〜3 | STS・DIAG・予備 | block |
| 4 | BoxTag | Node-RED |
| 5 | BoxItem | Node-RED |
| 6 | BoxWriter | Node-RED |
| 7 | 予備 | — |
| 8〜9 | BoxValue（REAL） | Node-RED |
| 10 | BoxSeq | Node-RED |
| 11 | 予備 | — |
| 12 | BoxAck | block |
| 13 | BoxResult | block |

- 計 14 ワード。**BoxSeq を Node-RED が書く範囲の最後（位置 10）に置いた**ので、位置 4〜10 を 1 回の書き込み（Modbus の複数レジスタ書き込み）で送れば、番号が中身より先に変わることはない（HMI 06 の 2 章 1「最後に番号を増やす」）。
- Ports は外に出さない（PLC の中だけ）。宛先のブロックの並びからは要求の口（各ブロックの 12〜19 など）を外す（各仕様書の「受付箱を使う構成では出さない」）。

## 10. PICOT HMI との対応

- Node-RED の対応表に「タグ → Tag の番号」の列を足す。画面定義の属性（`sp`・`mode`・`command`・`resetRequest`…）→ Item の番号は、ブロックの種類ごとの表（各仕様書の要求の口の項目）から引く。
- Result の番号 → 文は HMI 側の対応表（共通仕様 3 章）。15・16 の文を足す：「宛先のブロックがありません（対応表の誤り）」「PLC のブロックが応答しません」。

## 11. 決めたこと（2026-11-25）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 宛先の口へのつなぎ方 | **構造体の配列 `Ports` を受け渡し**、つなぐ行は対応表から作る呼び出しコードにする | FB に別の FB を渡す書き方は、対応していない機種がある（C-1）。配列なら多くの機種で書ける。宛先の追加は呼び出しコードの 2 行で済む |
| 2 | 口の数 | **64**（設定で 1〜64 を使う） | タンクのデモは 9 個（LT・TT・PT・LSHH・LIC・P・XV・IL と予備）。小さなユニット 1 つ分には十分。足りなければ受付箱ごと 2 つ目を置く（拡張版） |
| 3 | 返事が来ないとき | **TimeOut（既定 1 s）で結果 16**。宛先が無いときは結果 15。どちらも新しい番号 | Node-RED は 2 秒で「PLC が応答しません」にする（HMI 06）。PLC は動いているのに宛先を呼び忘れている、を区別して出せる |
| 4 | 生存カウンター | **このブロックに持たせる**（Alive） | 受付箱と同じ並びにあれば、Node-RED が 1 回の読み出しで両方見られる。別に作ると FB がもう 1 つ増える |
| 5 | 書いた人の確かめ | **しない**（運ぶだけ） | 判断は宛先のブロック（D-3）。ここでも確かめると、規則が 2 か所になる |

## 12. デモ（シミュレーター）での使い方（案）

- 今のシミュレーターは、画面の書き込みを各ブロックの要求の口へ直接入れている。これを「受付箱 → PB_ReqDispatch → 各ブロック」に変える。
- シミュレーターの書き込みはその場で結果を返す作りなので、書き込みのたびに dt = 0 のスキャンを数回回して返事を待つ（受付箱 → 宛先 → 返事で 2 スキャン）。dt = 0 なので、プロセスの時間は進まない。

## 13. テストベクタを起こして決めた細部（2026-11-25、案）

| # | 場面 | 決めたこと | 理由 |
|---|---|---|---|
| 13-1 | 1 スキャンの順番 | ①設定異常・Init → ②処理中なら返事を確かめる（口の AckSeq = Seq なら返事、そうでなければ待ち時間に dt を足し、TimeOut 以上なら結果 16）→ ③処理中でなく、②で返事をしておらず、BoxSeq ≠ BoxAck なら新しい 1 件を始める → ④Alive を進め、出力 | 1 スキャンに 1 件だけ動かす（3 章） |
| 13-2 | 返事と時間切れが同じスキャン | 返事を先に見る（返事が来ていれば時間切れにしない） | 宛先は処理を終えているので、その結果を返す方が正しい |
| 13-3 | 待ち時間の数え方 | 始めたスキャンで 0。次のスキャンから dt を足して比べる（dt は打ち切り後の値） | |
| 13-4 | 始めたスキャンの返事の確かめ | しない（宛先はまだ呼ばれていない） | |
| 13-5 | 口に書くもの | Item・Value・Writer・Seq は始めたスキャンにだけ書く。処理中に受付箱の中身が変わっても、口は変えない | 宛先が処理する前に値が変わらないように |
| 13-6 | 口の Seq の進め方 | 32767 の次は 1（0 は使わない） | 宛先の AckSeq の初期値 0 と区別するため |
| 13-7 | 結果 15 | 始めたスキャンで BoxAck・BoxResult を書き、処理中にしない | |
| 13-8 | DIAG bit3（時間切れ） | 時間切れで立て、次の 1 件を始めたスキャン（15 で返したときも）で消す。Init でも消す。設定異常のあいだは出さない（DIAG は設定異常だけ。戻ったスキャンは Init と同じなので消える。2026-11-25 追記、ST の確認で見つけた書き漏れ） | |
| 13-9 | Alive | Init・設定異常のスキャンでも進める。32767 の次は 0。Init で 0 に戻さない | Node-RED は「変わったか」だけを見る |
| 13-10 | 設定異常 | 処理中を外す。受付箱は見ない（BoxAck・BoxResult はそのまま）。戻ったスキャンは Init と同じ（BoxAck = BoxSeq） | 6 章 |

テストベクタの時間は 0.25 s の倍数で組む。
