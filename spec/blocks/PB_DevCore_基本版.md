## 1. 役割

2 つの状態（**on＝運転・開**、**off＝停止・閉**）を持つ機器を、指令・アンサーバック・インターロックで動かす共通の核。ポンプ（P-101）と ON/OFF 弁（XV-101）は、この核の設定違いで作る（12 章 論点 7）。

- 出力 `Out`（DO）：TRUE で on 側に動かす。
- 状態 `State`：**実際の位置**を出す。0 停止・閉（off）／1 運転・開（on）／2 動作中（transit：指令した動きの途中、または途中の位置）／3 位置が分からない（fault：リミットが両方 ON）。PICOT HMI の `state`（off・on・transit・fault）と同じ。起動失敗などの異常は State ではなく警報のビットで出す（運転員は「実際に回っているか」を見たいため）。
- 「on＝開・運転」に揃える理由：PICOT HMI の DV-P1（travel は開・運転側を 100 %）と揃えるため。

基本版に入れないもの（拡張版）：「動き出さない（固着）」と「途中で止まる」の区別（DV-2）、模擬・停止、バイパス、自己復帰型のインターロック（Siemens の Intlock [一次]）、モーターのトリップ入力（サーマル）、双方向（正転・逆転、電動弁の中間停止：B-10）。

## 2. 処理の順番

```
要求の口 → モード（MAN/AUT・現場）→ 指令の選択 → インターロック・パーミッシブ → 目標 → 出力
→ アンサーバックから今の位置 → アンサーバックの監視（4 パターン）→ 進み具合 → 運転時間・起動回数 → 状態ワード
```

| # | 処理 | 内容 |
|---|---|---|
| 1 | 要求の口 | 運転員の指令（項目 1）・モード（項目 2）、エンジニアの設定（9 章） |
| 2 | モード | MAN（運転員が指令）／AUT（プログラムが指令）。入力 `Local`（現場の切替スイッチ）が TRUE なら現場（3 章） |
| 3 | 指令の選択 | MAN：要求の口の指令。AUT：入力 `PCmdOn`・`PCmdOff` の立ち上がり（論点 3） |
| 4 | インターロック・パーミッシブ | 4 章 |
| 5 | 目標と出力 | 目標 `Target`（on／off）を決め、`Out` = Target が on |
| 6 | 今の位置 | 5 章（アンサーバックの有無の設定ごと） |
| 7 | アンサーバックの監視 | 6 章（4 パターン） |
| 8 | 進み具合 | 7 章 |
| 9 | 運転時間・起動回数 | 8 章 |

## 3. モード

| モード | 指令する人 | 運転員の指令（要求の口） | プログラムの指令 |
|---|---|---|---|
| MAN | 運転員 | 受け付ける | 無視する |
| AUT | プログラム（シーケンス） | 断る（結果 4） | 受け付ける |
| 現場（Local = TRUE） | 現場の押しボタン | 断る（結果 4） | 無視する |

- MODE ワード：0 MAN・1 AUT、bit8 現場（共通仕様 2 章）。MAN／AUT は運転員が要求の口（項目 2）で切り替える。現場は入力 `Local` で決まり、MAN／AUT とは別に持つ（現場から戻ると元の MAN／AUT）。
- MAN ↔ AUT を切り替えても目標は変えない（機器は動かない。バンプレス）。
- **現場のあいだは指令を受けず、失敗の監視もしない**。現場での操作への目標の合わせ方は 6.1（遠方と同じ規則）。
- **インターロックは現場でも効く**（目標を安全側にする）。理由（独自）：安全のための停止を現場の切替で外せないように。現場の盤が PLC を通らずに直接つながっている構成では、効くかどうかは配線で決まる（利用者向けの注意に書く）。
- PICOT HMI の `DiscreteDevice.mode`（遠方・現場）は bit8。MAN／AUT の属性は HMI に無いので、HMI 側で足す（11 章）。

## 4. インターロック・パーミッシブ

| 入力 | 意味 | 動き |
|---|---|---|
| `Intlk` | インターロック動作中（TRUE） | 目標を**安全側**（設定 `SafeState`、既定 off）にする。安全側でない向きの指令は断る（結果 9）。**Intlk が FALSE に戻っても、機器は安全側のまま**（新しい指令が来るまで動かない） |
| `Perm` | 起動の許可（TRUE で許可） | 安全側から**出る**指令のときだけ見る。FALSE なら断る（結果 14、新しい番号）。動いている最中に FALSE になっても止めない |

- ラッチ（リセットが要る）は、インターロックのブロック（B-12 `PB_Intlk`）が持つ。この核は「今インターロックが効いているか」の入力を受けるだけ。Siemens の分類の Protect（リセット要）と Permit に当たる。自己復帰型（Intlock）は拡張版 [一次 Siemens §2.1.4.1]。
- プログラムの指令（AUT）も同じ規則で断る（断ったことは DIAG bit3 で出す。要求の口の結果は運転員の指令の返事なので使わない）。
- 結果 14「起動条件が揃っていない」は共通仕様 3 章の表に足す。

## 5. 今の位置（アンサーバック）

設定 `FbCfg` でアンサーバックの有無を決める（DV-1）。

| FbCfg | つなぐもの | on 側にいる | off 側にいる |
|---|---|---|---|
| 3（既定） | 開（運転中）・閉の両方 | FbOn かつ NOT FbOff | FbOff かつ NOT FbOn |
| 1 | 開（運転中）だけ。ポンプの「運転中」接点など | FbOn | NOT FbOn |
| 2 | 閉だけ | NOT FbOff | FbOff |
| 0 | なし | 進み具合（7 章）が 100 % に着いた | 進み具合が 0 % に着いた |

- どちらにもいない → 途中。
- FbCfg = 3 で FbOn と FbOff が両方 TRUE → **リミット異常**（ALM bit2、すぐに）。State は 3。物理的にありえないため（Rockwell は両方 ON を故障にできる [一次 RM013]。DV-4）。両方 FALSE が長く続くのは 6 章の失敗で拾う。
- FbCfg = 0 は監視しない（失敗にならない）。

## 6. アンサーバックの監視（決定 2026-11-23：4 パターン）

「指令したか」と「安全側（`SafeState`）への動きか」で分ける。ポンプ（安全側＝停止）で書くと：

| # | パターン | 判断 | ブロックの動き |
|---|---|---|---|
| 1 | 指令なしでアンサーだけ起動（現場の MCC で起動など） | 正常の可能性が高い | 異常にしない。情報ビット「指令外の起動」。`FbTrack` = TRUE（ポンプ）なら**目標と DO を運転に合わせる**（遠方に戻しても運転を続ける）。FALSE（弁）なら目標は変えず DO は切ったまま → 下の 4 と同じに扱う |
| 2 | 起動を指令したのにアンサーが来ない | 異常 | `MonTOn` を過ぎたら **起動失敗**（ALM bit0） |
| 3 | 運転中に指令なしで停止（現場で停止、トリップなど） | 安全側 | 異常にしない。情報ビット「指令外の停止」。**目標を停止に合わせて DO を切る**（遠方に戻しても、トリップを戻しても再起動しない）。FbTrack に関係なく |
| 4 | 停止を指令したのにアンサーが切れない | 危険な異常 | `MonTOff` を過ぎたら **停止失敗**（ALM bit1） |

- 弁（XV-101、安全側＝閉）では「起動」を「開」、「停止」を「閉」と読む。**弁はアンサーで勝手に開けない**（FbTrack = FALSE）。指令なしで開いた弁は、閉の指令なのに開いている状態なので、`MonTOff` を過ぎたら閉失敗（ALM bit1）になる。
- SafeState = 1（安全側が開）の弁は、表の on と off を入れ替えて読む（「安全側への指令外の動き」は合わせる、「安全側でない向き」は FbTrack に従う）。
- 停止失敗（安全側の失敗）と起動失敗を別のビットにする理由：停止失敗は危険なので、HMI で高い優先度を付けられるように（優先度は HMI で持つ：A-6）。
- 1・3 の情報ビット（ALM bit3 指令外の on、bit4 指令外の off）は、次に指令（運転員・プログラム）が来るまで立てたままにする（Node-RED の読み取り周期で取りこぼさないように）。警報にするか、優先度をいくつにするかは HMI の画面定義で決める（3 はトリップでも起きるので、警報にしたい現場もある）。

### 6.1 判定の細部

- **指令した動き**：指令（運転員・プログラム）、インターロック、Init、失敗時の安全側への動きで目標が変わったら、「指令した動き」が始まる。今の位置が目標に着くまでの経過時間を数え、その向きの監視時間（MonTOn／MonTOff）以上なら失敗。着いたら終わり。指令した動きの途中は State = 2。
- **指令外の動き**：指令した動きがないとき（位置が目標にいるとき）に、位置が反対の端に移り、`StatT` 秒続いたら指令外の動きと判断する（接点のチャタリングで DO を切らないため。既定 1 s）。
  - 安全側へ → 目標を合わせる（3）。
  - 安全側でない側へ → FbTrack = TRUE なら目標を合わせる（1）。ただし**インターロック中は合わせない**（DO は切ったまま。下の失敗になる）。パーミッシブは見ない（現場の判断で起動したものなので）。FbTrack = FALSE なら合わせない。
  - 合わせなかったとき：位置が目標にいない状態が、目標の向きの監視時間続いたら失敗にする（弁の閉失敗など）。State は実際の位置。
- 途中の位置（FbCfg 3 で両方 OFF）で止まったままのときも、指令した動きなら監視時間で失敗。
- **失敗の戻り**：位置が目標に着いたら、そのスキャンで戻る。新しい指令（目標が変わった）でも戻り、経過時間を 0 から数え直す。リセットの操作は要らない（警報の確認と「復帰しても未確認なら残す」は HMI 側：A-5）。
- **失敗のときの動き**（DV-5）：設定 `FaultAct`：0 警報だけ（既定）・1 安全側へ動かす。
- **現場**（Local = TRUE）：指令を受けず、失敗の監視もしない。指令外の動きへの合わせ方は遠方と同じ規則（安全側へは合わせる、安全側でない側へは FbTrack に従う）。そのため弁を現場で開けても、遠方に戻すと DO は閉のまま（弁は閉じる）。
- 異常をシーケンスで使う出力 `Fault`（起動失敗・停止失敗・リミット異常のどれか。DV-8）。シーケンスを止めるかは利用者のシーケンスで決める。

## 7. 進み具合（DV-P1）

| 出力 | 内容 |
|---|---|
| `Travel` | 0〜100 %（on 側＝100）。アンサーバックで端にいると分かれば 0 か 100。途中は、ストローク時間 `StrokeT` で 100 % 動く速さで目標に向かって進めた推定値 |
| `Remain` | 目標に着くまでの残り時間の推定（s）＝ 残りの % × StrokeT / 100。着いたら 0 |

- 途中で向きが変わったら、今の推定位置から戻る（最初からやり直さない。PICOT HMI の今のデモと同じ）。
- 推定が端に着いてもアンサーバックが来なければ、Travel は端の値のまま、State は動作中（失敗の監視は続く）。
- StrokeT = 0 なら推定しない（目標の端にすぐ着いたことにする）。FbCfg = 0 では、この推定が位置そのものになる。

## 8. 運転時間・起動回数

- State が on のスキャンごとに運転時間を足す。**REAL で秒を足し続けると、大きな値で 0.1 s が足されなくなる**（REAL の有効桁は約 7 桁。194 日 ≒ 1677 万秒を超えると 1 s 未満が消える）。そのため「時間（DINT）」と「1 時間未満の秒（REAL）」に分けて持つ（独自。C-7）。
- 起動回数：State が on 以外から on に変わった回数（DINT）。指令ではなく実際の位置で数える。
- 運転時間・起動回数は**利用者のプログラムの保持領域**に置く（設定と同じ構造体。AnaMon 6.1）。機器を取り替えたときなどに、エンジニアが要求の口で書き換えられる（項目 20・21）。

## 9. 設定と要求の口

| 設定 | 型 | 既定値 | 範囲 | 要求の口 |
|---|---|---|---|---|
| `FbCfg` | INT | 3 | 0〜3 | 変えない（配線で決まる） |
| `SafeState` | INT | 0 | 0 off・1 on | 変えない |
| `FaultAct` | INT | 0 | 0 警報だけ・1 安全側へ | 変えない |
| `FbTrack` | BOOL | FALSE | 指令外に安全側でない側へ動いたとき、目標と DO を合わせるか（ポンプ TRUE・弁 FALSE） | 変えない |
| `StatT` | REAL | 1 | 0〜10 s。指令外の動きと判断するまでの時間 | 項目 13（エンジニア） |
| `MonTOn` / `MonTOff` | REAL | 10 / 10 | 1〜600 s（論点 5） | 項目 10・11（エンジニア） |
| `StrokeT` | REAL | 0 | 0〜600 s | 項目 12（エンジニア） |
| `RunHours` / `RunSecFrac` / `Starts` | DINT / REAL / DINT | 0 | 0 以上 | 項目 20（運転時間、時間）・21（起動回数）（エンジニア） |

| 項目番号 | 内容 | 書ける人 | 値 | 断る理由 |
|---|---|---|---|---|
| 1 | 指令 | 運転員・エンジニア | 0 off・1 on | 4（MAN でない・現場）、9（インターロック）、14（パーミッシブ） |
| 2 | モード | 運転員・エンジニア | 0 MAN・1 AUT | — |
| 10・11 | 監視時間 on 側・off 側 | エンジニア | s | 12 |
| 12 | ストローク時間 | エンジニア | s | 12 |
| 13 | 指令外の動きの判断時間 | エンジニア | s | 12 |
| 20・21 | 運転時間（時間）・起動回数 | エンジニア | 0 以上の整数 | 8・12 |

- 既定の監視時間 10 s は、小さな電磁弁に合わせず長めにした（DV-6。大型の弁は全開・全閉に 6 秒程度かかる [実務者の申告]）。
- 設定異常（計算できない設定）：MonTOn・MonTOff・StrokeT・StatT が NaN・無限大・負、FbCfg・SafeState・FaultAct が範囲外。設定異常のときは目標を安全側にし、監視しない（独自：何が起きるか分からない状態で機器を動かし続けないため）。

## 10. 時間・初期化

- dt は AnaMon と同じ（≦ 0 は進めない、1.0 s 超は打ち切り）。
- `Init` のスキャン（論点 6）：**目標を安全側にする**（PLC が止まって戻ったとき、DO は切れていたので機器は安全側にいるはず。それに目標を合わせる）。経過時間を 0、異常を消す。Travel はアンサーバックで分かれば端の値、分からなければ安全側の端。要求の口は AnaMon 13-10 と同じ（処理しない）。

| 5 | State | block |

## 13. 決めたこと（2026-11-23）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | アンサーバックの監視 | **決定**：6 章の 4 パターン（現場で起動＝正常、起動したのに来ない＝異常、指令なしで停止＝安全側、停止したのに切れない＝危険な異常）。指令外の起動に目標と DO を合わせるのは**ポンプだけ**（FbTrack）。弁はアンサーで勝手に開けない | 決定 |
| 2 | 失敗の戻りと失敗時の動き | **位置が目標に着くか、新しい指令で自動で戻る（リセット操作なし）**。失敗のときの動きは設定で選ぶ：警報だけ（既定）／安全側へ | 警報の確認は HMI で行うので、ブロックにリセットを持たせない（A-5 と揃える）。三菱・Rockwell はリセットを持つ [一次]。持つ方がよければ変える |
| 3 | MAN／AUT とプログラムの指令 | **基本版に MAN／AUT を入れる**。プログラムの指令は**立ち上がりの 2 本（PCmdOn・PCmdOff）** | DCS の機器と同じ感覚（G-5）。指令を「入れっぱなし」の 1 本にすると、インターロックが解けたとき勝手に再起動するため（三菱 RUN_SET／STOP_SET、Rockwell PCmd_Start／Stop と同じ形 [一次]） |
| 4 | インターロックとパーミッシブ | Intlk は安全側へ倒すだけで、解けても動かない（ラッチは PB_Intlk）。Perm は安全側から出るときだけ見る。断る理由に **14「起動条件が揃っていない」を足す** | Siemens の Protect と Permit と同じ [一次] |
| 5 | 監視時間の範囲（DV-7） | **1〜600 s**。「監視しない」は監視時間 0 ではなく、アンサーバックなし（FbCfg 0）で表す | 0 を「監視しない」にすると、設定し忘れと区別できない。1 s 未満は、スキャン周期によっては指令した最初のスキャンで異常になる |
| 6 | 初期化（電源投入）と現場 | Init で**目標を安全側**にする。現場のあいだは目標を今の位置に合わせ続け、インターロックは現場でも効く | 3 章・10 章 |
| 7 | ポンプ・弁の「薄い版」 | 基本版では**別の FB を作らず、設定の例**（ポンプ：FbCfg 1・FbTrack TRUE、弁：FbCfg 3・FbTrack FALSE）を仕様書に書く | 違いが設定だけなら、FB を分けると同じ試験が 3 倍になる。名前を分けたくなったら、核を呼ぶだけの FB を後で足す |

## 14. テストベクタを起こして決めた細部（2026-11-23、案）

安全側を S、安全側でない側を N と書く（SafeState = 0 なら S = off）。

| # | 場面 | 決めたこと |
|---|---|---|
| 14-1 | 1 スキャンの順番 | ①要求の口 → ②モード・Init → ③プログラムの指令 → ④インターロック → ⑤進み具合の推定（p を進める）→ ⑥今の位置 → ⑦監視（失敗・指令外）→ ⑧p の端合わせ → ⑨運転時間・起動回数 → ⑩出力・状態ワード。⑦で目標が変わったら（合わせた、FaultAct）、出力 Out は同じスキャンで変わる。経過時間は、指令したスキャンから dt を足す（BinMon の遅延と同じ数え方） |
| 14-2 | 受け付けた指令 | 目標をその値にし、失敗のビットと情報のビットを消す。今の位置が目標と違えば「指令した動き」を始める（経過時間 0）。同じ値の指令でも同じ（失敗した起動を、もう一度「起動」で試せる） |
| 14-3 | 要求の口の断る順番 | 項目が無い 1 → 書ける人 2 → 不正な値 8（NaN・無限大、指令・モードが 0/1 以外、運転時間・起動回数が整数でない）→ 指令：MAN でないか現場 4 → インターロック中に N へ 9 → 目標が S のときにパーミッシブ FALSE で N へ 14。設定：範囲外 12 |
| 14-4 | 範囲 | 運転時間・起動回数は 0〜9999999（REAL でちょうど表せる範囲）。運転時間を書いたら 1 時間未満の秒は 0 にする |
| 14-5 | プログラムの指令 | 前のスキャンからの立ち上がりで見る（モードに関係なく前の値を覚える。AUT にした瞬間に、入れっぱなしの指令で動かないように）。PCmdOn と PCmdOff が同じスキャンで立ち上がったら S 側を採る。断ったら DIAG bit3 |
| 14-6 | インターロック | Intlk が TRUE で目標が N なら、目標を S にする（14-2 と同じく失敗のビットを消し、指令した動きを始める。情報のビットは消さない）。現場・AUT でも同じ |
| 14-7 | 失敗のビットが消えるとき | (a) 位置が、失敗した向きの端に着いた、(b) 14-2 の指令・14-6 のインターロック・Init で目標が新しく決まった。**FaultAct で安全側に動かしたときは消さない**（起動失敗の警報が一瞬で消えないように） |
| 14-8a | 失敗した後 | 失敗した後は、その目標のまま静止中の監視（14-8）をしない（起動失敗のポンプを「指令外の停止」と見て目標を戻さないように）。位置が分からない（両方 ON）あいだも監視しない |
| 14-8 | 静止中（指令した動きがない）の監視 | 位置が目標と違う（途中、または反対の端）あいだ、経過時間を足し、目標の向きの監視時間以上で失敗。反対の端にいるあいだは別に StatT を数え、StatT 以上で指令外の動きと判断する（6.1）。目標に合わせたら経過時間を 0 にする。位置が目標に戻ったら両方 0 |
| 14-9 | 情報のビット | 指令外の動きと判断したとき、動いた向きのビット（on へ：bit3、off へ：bit4）を立てる（合わせたかどうかに関係なく）。14-2 の指令と Init で消す |
| 14-10 | 現場 | 指令した動き・静止中の経過時間を数えない（失敗にしない）。StatT の判断と目標の合わせ方は遠方と同じ |
| 14-11 | 進み具合の推定 | ⑤で推定値 p を、目標の端へ 100 × dt / StrokeT だけ進める（端で止める。StrokeT = 0 なら端へ）。FbCfg = 0 では p が 100 なら on、0 なら off、その間は途中。⑧（FbCfg ≠ 0）：位置が端にいて「目標と同じ端」「指令した動きの途中でない」「失敗している」のどれかなら p をその端にする（ポンプのように片方のアンサーしか無くても、起動の途中は推定で進む。失敗したら実際の位置を出す） |
| 14-12 | Remain | 指令した動きの途中で、失敗していないとき：（目標の端 − p の差）× StrokeT / 100。それ以外は 0 |
| 14-13 | State | 位置が分からない（両方 ON）→ 3、指令した動きの途中で失敗していない → 2、それ以外は位置（途中 → 2） |
| 14-14 | 起動回数・運転時間 | 位置が on のスキャンで運転時間に dt を足す。位置が「前のスキャンで on でない → on」で起動回数を 1 足す（Init のスキャンは数えない） |
| 14-15 | Init | 目標 S、失敗・情報のビットを消す、p は位置が端ならその端、分からなければ S の端。プログラムの指令の前の値を今の値にする。位置が S でなければ指令した動き（止める）として監視する |
| 14-16 | 設定異常 | 目標を S にし、失敗・情報のビットを消し、監視しない。戻ったスキャンは Init と同じ |

テストベクタの時間は 0.25 s の倍数で組む。
