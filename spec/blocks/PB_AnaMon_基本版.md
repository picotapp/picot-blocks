## 1. 役割

4〜20 mA などのアナログ入力を工学値の PV にし、計器故障の判定、フィルタ、上下限警報（HH・H・L・LL）、品質を出す。運転員の手動・自動は持たない（M-1）。

基本版に入れないもの（拡張版）：HH〜LL の警報ごとの ON 遅延（故障の ON 遅延は基本版に入れる）、変化率警報、代替値、NE107 診断の入力、抑制（Suppress）。拡張版はこの仕様のデータの並びの**後ろに足す**（AI-10）。

## 2. 処理の順番

```
入力の選択 → 生値 → mA → 計器故障の判定 → 工学値 → フィルタ → 故障時の PV → 警報 → 品質 → 状態ワード
（模擬なら模擬値）  （NE43）                                  （保持）
```

| # | 処理 | 内容 | 根拠 |
|---|---|---|---|
| 1 | 入力の選択 | 模擬中は `SimValue`（工学値）を使い、2〜4 と 6 を飛ばす（フィルタ・警報は通す。13 章）。それ以外は入力 `In`（生値） | AI-9。三菱 P_IN も SIM で入力を差し替える [一次] |
| 2 | 生値 → mA | 入力 `In` は **AI ユニットのディジタル値（分解能のカウント値。例：4〜20 mA → 0〜32000）**で、mA ではない。`InType = 0`（4〜20 mA）のとき、`RawLo` = 4 mA のときのカウント、`RawHi` = 20 mA のときのカウントとして、mA = 4 + 16 ×（In − RawLo）/（RawHi − RawLo） | 独自：AI ユニットの生値の範囲は機種ごとに違うため（例：0〜32000、0〜4000 など）、生値の範囲を設定で持つ |
| 3 | 計器故障の判定 | 3 章 | AI-3、NE43（広く紹介されている値。規格本体は未確認） |
| 4 | 工学値 | 割合 x =（In − RawLo）/（RawHi − RawLo）、PV' = EuLo + x ×（EuHi − EuLo）。**レンジ外でも切らない**（−1.25 % や 103 % もそのまま出す） | AI-2。切らない理由（独自）：レンジ外を運転員に見せるため。品質で Uncertain を付ける |
| 5 | フィルタ | 一次遅れ。y ← y +（PV' − y）× dt /（FilterT + dt）。FilterT = 0 で素通し | AI-4。式は時定数と dt から係数を出す形（三菱は係数 α を直接設定 [一次]）。この形は dt が大きくても値が振動しない（独自） |
| 6 | 故障時の PV | 計器故障中は**最後の正常な値を保持**（既定）。設定 `FailMode = 1` で入力をそのまま通す | AI-7 の基本版の範囲。三菱はプロジェクト全体で保持を選ぶ [一次] |
| 7 | 警報 | 4 章 | A-1〜A-4 |
| 8 | 品質 | 5 章 | Q-1、M-4 |

## 3. 計器故障の判定（InType = 0 のとき）

| 条件 | 判定 | 品質 |
|---|---|---|
| mA ≦ `FailLo`（既定 3.6）または mA ≧ `FailHi`（既定 21.0）、または入力 `ChFault`（AI ユニットの断線ビット）が TRUE | **計器故障**になる | Bad（計器） |
| 計器故障中に、mA が `OorLo`（既定 3.8）〜`OorHi`（既定 20.5）に戻り、かつ ChFault が FALSE | 計器故障が**戻る** | 下の行による |
| 4.0 ≦ mA ≦ 20.0 | 正常 | Good |
| それ以外（3.6 < mA < 4.0、20.0 < mA < 21.0 で故障中でない） | レンジ外だが有効 | Uncertain（プロセス） |

- **故障の ON 遅延 `FailDelay`**（s、既定 0 = なし）：故障の条件（判定点を外れた、または ChFault）が `FailDelay` 秒続いたら計器故障にする。一瞬のノイズで「計器故障 → 調節計が MAN に落ちる」のを防ぐため（Rockwell は故障の警報に ON 遅延を持つ [一次]）。
  - 遅延中（故障の疑い）は、**PV を最後の正常な値で保持し、HH〜LL の警報は今の状態のまま変えない**。品質は Uncertain（計器）、DIAG bit5 を立てる。理由（独自）：断線すると入力は 0 mA（−25 %）に落ちるので、遅延中に計算どおりの PV を出すと、L・LL の警報が誤って出る。
  - 戻りには遅延を付けない（条件が消えたら、そのスキャンで疑いを解く）。
- 故障の判定点（3.6／21.0）と戻り点（3.8／20.5）を分けて、判定のばたつきを防ぐ（三菱は異常と復帰を別設定 [一次]。値は NE43 として広く紹介されている数字を使う。規格本体は未確認）。
- 3.6〜3.8 mA・20.5〜21.0 mA の NE43 上の扱いは未確認。この仕様では「故障中でなければ Uncertain」とする（独自）。
- `InType = 1`（4〜20 mA でない入力：測温抵抗体のユニットなど）は mA を計算せず、この章の判定を行わない。ChFault だけで計器故障にする。RawLo／RawHi は EuLo／EuHi に当たるカウントになる。
- **ユニットの設定によっては、4 mA 未満や 20 mA 超のカウントを出さない（0〜32000 で切る）**。その場合はカウントから 3.6 mA・21 mA を判定できないので、ユニットの断線検出・範囲外検出のビットを `ChFault` につなぐ。どちらで判定するかは、使うユニットの仕様（範囲外のカウントを出せるか）を確かめて利用者が決める。仕様書の利用者向けの注意に書く [ユニットごとの範囲は未確認]

### 3.1 判定点は計器に合わせて決める

伝送器が故障のときに出す電流は、機器と設定で違う。**低い側は 1 つの値で全部を正しく判定できない**（例：ある機器の標準設定は 3.75 mA 以下で故障を知らせるが、別の機器は正常でも 3.68 mA まで下がる）。そのため判定点は設定で持ち、既定値は NE43 にする。利用者向けの説明に、判定点の決め方の表を付ける：

| 計器の設定 | FailLo | OorLo | OorHi | FailHi |
|---|---|---|---|---|
| NAMUR NE43 に揃えた計器（既定） | 3.6 | 3.8 | 20.5 | 21.0 |
| 故障時 ≦ 3.75 mA・飽和 3.9〜20.8 mA の計器 | 3.8 | 3.9 | 20.8 | 21.0 |
| 故障時 ≦ 3.6 mA・飽和 3.68〜20.8 mA の計器 | 3.6 | 3.68 | 20.8 | 21.0 |

- 高い側は、調べた機器はすべて 21 mA 以上を出すので 21.0 で拾える。
- 製品名は説明の中だけで使い、FB の名前・変数には使わない（N-2）。
- PLC の AI ユニットが 4 mA 未満・20 mA 超のカウントを出せない場合は、ユニット側の検出を `ChFault` につなぐ（3 章の注意）。ユニットによっては下側だけ見えて上側（20 mA 超）が見えないものがあるので、そのときは上側をユニットの入力信号異常の検出で拾う。

## 4. 警報（HH・H・L・LL）

| 段 | 発生 | 戻り |
|---|---|---|
| HH・H | PV ≧ 設定値 | PV ＜ 設定値 − Hys |
| L・LL | PV ≦ 設定値 | PV ＞ 設定値 ＋ Hys |

- 判定に使う PV はフィルタ後の値（処理 5 の後）。
- ヒステリシス `Hys` は 4 段で共通の 1 値、**工学値で持つ**（A-2）。三菱は % で持つ [一次]。工学値にする理由（独自）：画面の警報設定値と同じ単位で見られる。PICOT HMI も工学値。
- **境界上の値（PV = 設定値）で発生**する（≧。決定）。三菱は「＞」[一次]。≧ にする理由（独自）：PICOT HMI のデモが ≧ で、設定値ちょうどで警報が出る方が運転員の感覚に合う。
- 警報ごとに検出の有効・無効（`Inh` のビット、エンジニア）。無効にした段は発生しない。発生中に無効にしたら、その場で消える（A-4）。
- 計器故障中、停止中は 4 段とも出さない（AI-8、M-4）。計器故障は別のビット（ALM bit4）で出す。
- 模擬中は模擬値で判定する（模擬で警報の動きを試せるように。Siemens も同じ [一次 §2.1.1.9 の趣旨]）。
- 確認（ACK）・ラッチ・優先度は持たない（A-5・A-6）。
- レンジ外だが有効（Uncertain）のときも警報は判定する（例：PV 103 % で HH）。

## 5. 品質とモード

| 状態 | STS の品質（bit3〜4） | 原因（bit5） | 操作された値（bit6） |
|---|---|---|---|
| 正常 | 0 Good | — | 0 |
| レンジ外だが有効 | 1 Uncertain | 0 プロセス | 0 |
| 計器故障、設定異常 | 2 Bad | 1 計器 | 0 |
| 停止中（Out of service） | **3 停止中** | — | 0 |
| 模擬中 | 0 Good | — | **1** |

- モードは「運転中（On）／停止中（OOS）」の 2 つ（M-1）。停止中は PV を保持し、警報を出さない（M-4）。
- 模擬は停止中とは別（M-3）。模擬中に停止にしたら停止が優先（警報も出さない）。
- 設定異常（6 章）のときは PV を計算せず保持し、Bad（計器）。

## 6. 設定とその検査（C-8）

| 設定 | 型 | 既定値 | 書ける範囲（要求の口で検査） |
|---|---|---|---|
| `InType` | INT | 0 | 0・1 |
| `RawLo` / `RawHi` | REAL | 0 / 32000 | 有限、RawLo ≠ RawHi。InType = 0 では 4 mA・20 mA のときのカウント |
| `EuLo` / `EuHi` | REAL | 0 / 100 | 有限、EuLo ＜ EuHi。有効な警報設定値がすべて新しいレンジ内に入ること |
| `FilterT` | REAL | 0 | 0〜3600 s |
| `LimHH` / `LimH` / `LimL` / `LimLL` | REAL | 100 / 100 / 0 / 0 | レンジ内。**有効な段どうしで** LL ＜ L ＜ H ＜ HH |
| `Hys` | REAL | 0 | 0〜スパンの 10 % |
| `Inh` | WORD | 16#000F（4 段とも無効） | bit0 HH・bit1 H・bit2 L・bit3 LL |
| `FailMode` | INT | 0 | 0 保持・1 通す |
| `FailLo` / `OorLo` / `OorHi` / `FailHi` | REAL | 3.6 / 3.8 / 20.5 / 21.0 | FailLo ≦ OorLo ≦ 4.0、20.0 ≦ OorHi ≦ FailHi（計器ごとに変える。3.1 節） |
| `SimValue` | REAL | 0 | 有限 |
| `FailDelay` | REAL | 0 | 0〜10 s（試運転の設定。要求の口では変えない） |

- 要求の口を通らずに入った値（プログラムの初期値、Modbus で直接書かれた値）も毎スキャン確かめ、おかしければ**設定異常**（STS bit7・DIAG bit1）にして計算しない。NaN・無限大・0 での割り算を起こさない（C-8：三菱は演算エラーで CPU が止まる [一次]）。
- 既定で警報を無効にしておく理由（独自）：設定前の既定値で警報が鳴り続けないように。
- 範囲の数字（FilterT 3600 s、Hys 10 %）は PICOT HMI の `paramRules` と揃える［HMI 側の FilterT は未実装］。

### 6.1 設定の持ち方（決定）

案：設定は構造体 `PB_AnaMon_Cfg` にまとめ、**利用者のプログラムが保持領域（ラッチ）に宣言して FB に `VAR_IN_OUT` で渡す**。FB は要求の口で受けた変更を検査してから、この構造体に書く。

- 理由：初期値を利用者のプログラムの宣言で与えられる（C-4 のとおり FB の中の初期値に頼らない）。保持（リテイン）の指定も利用者側で機種に合わせてできる（保持の指定の仕方は機種ごとに違う。OpenPLC は RETAIN）。
- Modbus への出し方：FB の構造体を直接の番地にはしない。番地に写すのは機種ごとの「アダプタ」（生成したコード）の役目（計画の「層構造」）。

## 7. 時間・初期化（C-2〜C-4）

- `dt`（s、REAL）を毎スキャン入力で受ける。dt ≦ 0 なら時間を進めない（フィルタを動かさない）。dt ＞ 1.0 s なら 1.0 s で打ち切り、そのスキャンの間 DIAG bit0 を立てる。
- `Init` が TRUE のスキャン：フィルタの値を今の入力の工学値に合わせ、計器故障と警報を消してから、同じスキャンで判定し直す。PV の保持値も今の値にする。初回スキャンに TRUE にするのは利用者の配線（機種が持つ初回スキャンのフラグなど）。

## 8. 入出力（FB のインターフェース）

| 区分 | 名前 | 型 | 内容 |
|---|---|---|---|
| 入力 | `In` | REAL | 生値＝AI ユニットのディジタル値（分解能のカウント値）。mA ではない。INT は利用者が REAL にして入れる |
| 入力 | `ChFault` | BOOL | AI ユニットの断線・異常ビット |
| 入力 | `dt` | REAL | 前回からの時間（s） |
| 入力 | `Init` | BOOL | 初期化 |
| 入力 | `ReqSeq` / `ReqItem` / `ReqValue` / `ReqWriter` | INT / INT / REAL / INT | 要求の口（D-7） |
| 入出力 | `Cfg` | PB_AnaMon_Cfg | 設定（6 章） |
| 出力 | `PV` | REAL | 工学値 |
| 出力 | `mA` | REAL | 入力の mA 換算値（保守用。InType = 1 では 0） |
| 出力 | `STS` / `MODE` / `ALM` / `DIAG` | WORD | 状態ワード（共通仕様 2 章） |
| 出力 | `HH` / `H` / `L` / `LL` / `Fail` | BOOL | 警報（インターロックの原因などに使う。ALM と同じ内容） |
| 出力 | `Bad` | BOOL | 品質が Bad または停止中（次のブロックに渡す用。J-2） |
| 出力 | `AckSeq` / `Result` | INT | 要求の口の返事 |

状態ワードのビット：

| ワード | ビット |
|---|---|
| STS | 共通（bit0 運転中・1 停止中・2 模擬中・3〜4 品質・5 原因・6 操作された値・7 設定異常・8 dt 打ち切り） |
| MODE | 常に 0（監視ブロック） |
| ALM | bit0 HH・1 H・2 L・3 LL・4 計器故障 |
| DIAG | bit0 dt 打ち切り・1 設定異常・2 ChFault または入力 In が数でない（13-21）・3 NE43 下側の故障・4 NE43 上側の故障・5 故障の疑い（ON 遅延中） |

## 13. テストベクタを起こして決めた細部（2026-11-23、案）

| # | 場面 | 決めたこと | 理由 |
|---|---|---|---|
| 13-1 | 1 スキャンの順番 | ①要求の口を処理（設定・モードの変更）→ ②モード・Init → ③入力・故障の判定 → ④工学値・フィルタ → ⑤PV → ⑥警報 → ⑦品質・状態ワード。要求で変えた設定は、同じスキャンの判定から効く | 結果が 1 スキャン遅れないように |
| 13-2 | 故障の疑い・計器故障の間のフィルタ | フィルタの値を**止める**（更新しない）。戻ったら止めた値から続ける | 壊れた入力（0 mA など）をフィルタに入れない |
| 13-3 | 「最後の正常な値」 | 故障の疑い・計器故障になる直前のスキャンの PV 出力（レンジ外だが有効の値を含む）。保持中は PV 出力を更新しない | 定義をはっきりさせるため |
| 13-4 | FailMode = 1（通す）の PV | フィルタを通さない計算値（処理 4 の PV'）をそのまま出す。故障の疑い（遅延中）は FailMode に関係なく保持 | 故障中の生の値を見たいときの設定のため |
| 13-5 | 故障の戻り点 | OorLo ≦ mA ≦ OorHi（両端を含む）で戻る | |

### 13.1 テストベクタの境界値と REAL の丸め（NF-3）

- 「設定値ちょうど」の試験は、2 進数でちょうど表せる値で組む。例：RawLo 0・RawHi 32768・EuLo 0・EuHi 128 にすると PV = In / 256、mA = 4 + In / 2048 がちょうどになる。判定点も 3.5・3.75・20.5・21 のようにちょうど表せる値にする。
- dt と FailDelay・FilterT も 0.25 のようにちょうど表せる値にする（0.1 を 10 回足しても 1.0 ちょうどにならないため）。
- 既定値（3.6・3.8 mA など）は、境界から十分離れた値で試す。
