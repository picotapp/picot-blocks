# 拡張：インターロックのバイパス（PB_Intlk）v0.2

根拠の表記：[一次] は各社の公開マニュアルで確かめたこと（文書番号・章）。「独自」はこのライブラリの設計判断で、理由を書く。

対象：`PB_Intlk_基本版.md` の拡張。**基本版のデータの並びの後ろに足す**。

---

## 0. 自己復帰型について（もうあるもの）

Siemens の 3 分類 [一次] のうち：

| Siemens | PICOT Blocks |
|---|---|
| Permit（起動の許可） | PB_DevCore の `Perm` 入力（基本版にある） |
| Intlock（条件が消えれば自動で戻る） | PB_Intlk の **自動リセット（`ResetMode` = 1）**（基本版にある） |
| Protect（リセットが要る） | PB_Intlk の手動リセット（`ResetMode` = 0、既定） |

→ **自己復帰型は足さない**。足すのはバイパスだけ。

## 1. バイパス（原因ごとの無効化）

試運転・保守で、計器を外す・校正する間、その原因でトリップしないようにする。**安全のための仕組みを外す操作**なので、誰がいつ外したかが分かり、外しっぱなしにならないことを一番に考える。

| 項目 | 案 |
|---|---|
| どの原因をバイパスできるか | 設定 `BypAllow`（WORD、bit0〜7 ＝ 原因 1〜8）。**C&E 表の列**で決める（既定 0：どれもできない） |
| 誰が | **エンジニアだけ**（要求の口 項目 2：バイパスする原因のビット、項目 3：バイパスを外す原因のビット） |
| 時間 | 設定 `BypMaxT`（s、既定 8 時間）を過ぎたら**自動で外す**（外しっぱなしにしない） |
| バイパス中の原因 | `Cause` に入れない（トリップしない）。`Raw` にはそのまま出す（画面で「入っているがバイパス中」が見える） |
| トリップ中にバイパス | **断る**（結果 9：インターロック中）。トリップを外すためのバイパスにしない。リセットしてからバイパスする |
| バイパスを外したとき、原因が入っていたら | そのスキャンでトリップする（遅延があれば遅延から数える） |
| 知らせる | 出力 `Byp`（WORD）、`BypOn`（BOOL：どれか 1 つでもバイパス中）。**ALM bit0「バイパス中」を出す**（論点 3） |

- 電源投入（Init）：**バイパスを外す**（論点 4）。保持しない。
- リセットの判定（ResetReady）は、バイパス中の原因を除いて見る。

## 2. 要求の口の項目（足すもの）

| 項目 | 内容 | 書ける人 | 値 | 断る理由 |
|---|---|---|---|---|
| 2 | バイパスする | エンジニア | 原因のビット（1〜255） | 8（整数でない・範囲外）、12（BypAllow に無い原因）、9（トリップ中） |
| 3 | バイパスを外す | エンジニア・運転員 | 原因のビット | 8 |

- 外すのは運転員でもできる（安全側の操作のため）。

## 3. Modbus の並び（基本版 36 ワードの後ろ）

| 位置 | 中身 |
|---|---|
| 36 | Byp（今バイパス中の原因） |
| 37 | BypAllow |
| 38〜39 | BypMaxT（REAL） |
| 40〜41 | BypLeft：バイパスの残り時間（REAL、一番短いもの。無ければ 0） |

## 4. 設定

| 設定 | 型 | 既定値 | 範囲 |
|---|---|---|---|
| `BypAllow` | WORD | 0 | bit0〜7 |
| `BypMaxT` | REAL | 28800 | 60〜86400 s |

- 要求の口では変えない（C&E 表が元。基本版 6 章と同じ）。

## 6. 論点（決定済み 2026-11-26：すべて案どおり）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 誰がバイパスできるか | **エンジニアだけ**（外すのは運転員も） | 安全の仕組みを外す操作。Rockwell も Maintenance（保守員）に限っている [一次 RM013 Table 21] |
| 2 | 時間切れ | **8 時間で自動的に外す**（設定で 1 分〜24 時間） | 外しっぱなしが一番の事故の元。シフト 1 回分を既定にした（独自） |
| 3 | 警報 | **バイパス中は ALM bit0 を出す**（基本版の「ALM は常に 0」を変える） | バイパスは原因のブロックの警報と重ならない、別の事実。画面に出し続ける必要がある |
| 4 | 電源投入 | **バイパスを外す** | 保持すると、入れ直しのあと気付かないまま外れている。外した結果トリップするなら、それは正しい |
| 5 | AND・2oo3（原因の組み合わせ） | **今回は入れない**（別の拡張） | バイパスと 2oo3 は組み合わせの規則（2oo3 の 1 つをバイパスしたら 1oo2 になる、など）を決める必要がある |

## 7. 注意

- これは計装の運転のためのインターロック（BPCS）のバイパス。**安全計装（SIS）のバイパス管理の代わりにはならない**（PICOT Blocks は SIS に使えない。公開ページの「ご利用にあたって」）。

## 8. 細かい決まり（テストベクタと実装の元）

- 8-1 処理の順番：基本版の ② 要求の口の後に **バイパスの時間**を入れる：バイパス中の原因ごとに経過時間へ dt を足し、BypMaxT 以上で外す。その後の ④ 遅延・⑤ トリップは、**Raw からバイパス中の原因を除いたもの**で判定する。
- 8-2 バイパスした（項目 2）スキャンで、その原因の経過時間を 0 にしてから 8-1 で dt を足す（そのスキャンの終わりの残り時間は BypMaxT − dt）。すでにバイパス中の原因をもう一度バイパスすると、時間を数え直す。
- 8-3 出力 `BypLeft`（REAL）：バイパス中の原因のうち一番短い残り時間。バイパスが無ければ 0。
- 8-4 BypAllow から外した原因（Modbus で直接書かれた場合など）は、そのスキャンでバイパスを外す。
- 8-5 **BypAllow = 0 のときは BypMaxT を見ない**（基本版の設定のままで、今までと同じに動く）。BypAllow ≠ 0 のとき BypMaxT が 60〜86400 の外・数でないなら設定異常。BypAllow の bit8〜15 が立っていれば設定異常。
- 8-6 設定異常・Init：バイパスを外す。
- 8-7 要求の口の断る順番：項目 2：項目 → 書ける人（エンジニアだけ、2）→ 値（1〜255 の整数でなければ 8）→ 設定異常（11）→ BypAllow に無い原因（12）→ トリップ中（9）。項目 3：項目 → 書ける人（運転員・エンジニア、2）→ 値（8）。項目 3 はバイパスしていない原因を外しても 0（何もしない）。
- 8-8 リセットの判定（ResetReady、項目 1 の 11、自動リセット）は、Raw からバイパス中の原因を除いたもので見る。
- 8-9 ALM bit0 ＝ BypOn。
