# 書き方の検査（C-1〜C-8）

`st/*.st` を、要件定義 4.1 の書き方の決まりと、STruC++・他社の PLC で困る書き方で検査する（NF-1）。OpenPLC で通ってもほかの機種で通らない書き方を、コンパイルの前に見つけるため。

```
node check.mjs            # st のすべて
node check.mjs a.st b.st  # 指定したファイル
```

誤りがあれば終了コード 1。

| 印 | 見るもの |
|---|---|
| C-1 | 標準関数・型変換（`*_TO_*`）・ライブラリの FUNCTION・FB 以外の呼び出し。METHOD・PROPERTY・EXTENDS など |
| C-2 | タイマー FB（TON・TOF・TP など）の宣言 |
| C-4 | 宣言の初期値（構造体の型の中は除く） |
| C-5 | `w.0` のようなビット参照 |
| C-6 | STRING・POINTER・REF_TO・REFERENCE・ADR・`^`・可変長の配列 |
| C-7 | LREAL |
| C-8 | 変数で割る所・MOD・SQRT・LN・LOG・EXPT |
| 名前 | 大文字・小文字だけ違う名前、EN・ENO、C・C++ の名前（NAN など）とぶつかる名前 |
| FOR | 数え上げの変数の型の上限まで回す FOR（あふれて終わらない） |

- C-8 と C-4 は、ソースを読むだけでは正しいか決められない。**同じ行か 1 行上の注釈**に `C-8：割る数が 0 にならない理由` や `C-4 例外：理由` を書けば認める（C-4 は注意として残す）。理由は試験（テストベクタの NaN・設定異常の場面）で確かめる。
- 正しく見つけるかは、ルールごとに違反を入れた ST で確かめた（2026-11-25、13 件すべて）。
- CONFIGURATION（タスクの宣言）は書き方の決まりの外なので見ない。ブロックを使うプログラム（例：PICOT HMI のタンクのデモ）も、ブロックのファイルと一緒に渡せば検査できる
- 見ないもの：NaN・無限大を計算に入れないこと（C-8 の残り。テストベクタで確かめる）、C-3（dt の扱い。テストベクタで確かめる）。
